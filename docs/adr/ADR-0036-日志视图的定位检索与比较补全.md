# ADR-0036: 日志视图的定位、检索与比较补全

**状态：** 提议中
**创建时间：** 2026-11-09

> **当前状态 / 核心结论：** 提案尚未实施。补齐日志视图的四个读侧缺口：跳到任意 hash / 分支 / 标签、按代码内容检索提交、任意两提交比较、提交所在分支计数。下一步：确认后按 A→B→C→D 顺序实施。

---

## 背景

当前日志视图只能 `Go to HEAD`，只能按消息 / 作者 / 路径过滤，比较只支持「与父提交」或「与当前 HEAD」。用户已知一个 hash 或一行代码却无法在日志里直接落位。

## 决策

1. **任意目标跳转**：`Ctrl/Cmd+G` 打开输入框，支持完整或前缀 hash、本地 / 远程分支短名、标签名；命中 ref 时切到该 Branch 筛选并定位首行，命中 hash 时清空与之冲突的筛选后定位，并在输入框内提示「已清空筛选」。
2. **内容检索**：Text 筛选旁增加「内容」模式（精确 / 正则），分别走 `git log -S` 与 `git log -G`；该模式只在显式开启时生效，默认仍按消息、作者姓名与邮箱扫描。
3. **任意两提交比较**：多选恰好两个提交时，Commit 菜单出现「Compare Selected Commits」，复用现有 Commit Comparison 页面与 Diff 打开路径。
4. **提交所在分支计数**：Commit Details 懒加载 `git branch --contains <hash>`，展示「位于 N 个分支」并可展开列表；不并入列表主查询。
5. **不做什么**：不建全文索引、不做跨仓库检索；自绘 Inline Diff 的「忽略空白」开关不在本轮（原生 Diff 已继承 VS Code 设置）。

## 后果

- **收益：** 已知 hash / 代码片段即可直达，省去反复换筛选。
- **代价 / 权衡：** `-S` / `-G` 需扫描全历史，大仓库上明显慢于消息扫描，必须有取消与超时；分支计数是额外一次命令。
- **降级方向：** 内容检索超时或取消时保留上一次结果并提示，不回退成静默空列表。
- **未解决风险：** 前缀 hash 在浅克隆或过滤后的窗口中可能不可见，跳转会落到「不在当前结果集」——需明确提示而非静默失败。
