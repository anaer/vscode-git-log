# ADR-0034: 托管平台跳转与链接复制

**状态：** 提议中
**创建时间：** 2026-11-09

> **当前状态 / 核心结论：** 提案尚未实施。为提交、变更文件与编辑器当前行增加「在托管平台打开」与「复制链接」，URL 由 `git remote get-url` 推导并按托管商模板拼装；无法识别托管商时隐藏入口而不猜测。下一步：确认后进入 design，产出模板表与降级用例。

---

## 背景

日志视图目前是只读本地视图，用户定位到某个提交或文件后仍需手工到浏览器找对应页面；扩展内没有任何 remote URL 解析与链接生成能力。

## 决策

1. **Remote 解析与缓存**：按当前分支上游取 remote（`branch.<name>.remote`），无上游回退 `origin`；`git remote get-url` 每个仓库只取一次并随引用快照下发，解析失败不缓存、下次刷新重试。
2. **托管商模板**：内置 GitHub、GitLab、Bitbucket、Gitea、Azure DevOps 五种，拼三类目标——提交、文件、行区间；文件链接中的 ref 固定用提交 hash 而非分支名，避免链接随分支移动失效。
3. **入口**：Commit 右键「Open Commit on <Host>」/「Copy Commit Link」；Changed File 右键「Open File on <Host>」/「Copy File Link」；编辑器 `Git Log` 子菜单增加「Open Line on <Host>」，携带当前选中的行号区间。
4. **降级**：无法识别托管商（无 remote、本地路径 remote、SSH 别名不可解析）时**隐藏**入口，不拼接可能 404 的链接；拼接与复制前剔除 URL 中的 userinfo 与 token。
5. **不做什么**：不做 PR / Issue 列表、不做代码搜索跳转、不内嵌浏览器；自建实例的非常规 URL 形态不在本轮范围（登记为延后）。

## 后果

- **收益：** 从日志到网页一步直达，链接可直接贴进 issue 或 IM。
- **代价 / 权衡：** 需维护托管商模板矩阵，新增平台要改代码并补用例。
- **降级方向：** 保守——识别不出托管商就不显示入口，宁可少一个按钮也不给坏链。
- **未解决风险：** SSH 别名（`git@host-work:org/repo`）与反向代理子路径无法从 URL 推断；Azure DevOps 的 `_git` 路径需独立模板。
