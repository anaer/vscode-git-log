# ADR-0001: VSCode Git Log 扩展优化方案

**状态：** 已接受
**创建时间：** 2026-09-04
**更新时间：** 2026-09-07

**背景：**

项目分析发现多个可优化点，涵盖性能、代码质量、架构和健壮性。当前扩展使用 `onStartupFinished` 激活策略影响启动性能，App.tsx 单文件过大（~2000行）违反单一职责原则，LRU 缓存实现效率低，文件系统监控缺乏错误处理。

**决策：**

按优先级分阶段实施优化：

### 高优先级（立即执行）

1. ~~**移除 `onStartupFinished` 激活策略**~~ (`package.json:33`) — **已评估，否决（维持现状）**
   - 原计划：改为依赖 `onView:gitLogWorkbench.log` 懒加载
   - **否决原因（2026-09-07）**：当前行 blame 装饰（`currentLineBlame.enabled` 默认 `true`）依赖激活时注册的 `onDidChangeActiveTextEditor`/`onDidChangeTextEditorSelection` 监听（`extension.ts:457-460`）。移除后 blame 需到首次使用 Git Log 命令才生效，属行为回归，用户确认维持现状
   - 影响：所有用户启动时间减少，仅使用 Git Log 时才加载

2. **拆分 App.tsx** (`webview/src/App.tsx`) — **已完成（详见 ADR-0003，4 轮拆分全部交付，4301→约 2212 行）**
   - 引入 Zustand 外部 store 解决闭包镜像 ref 问题
   - 渐近式拆分：对话框 → context menu → 各面板 → 共享 store
   - 对外契约简单（App 无 props），拆分不改变 index.tsx 与测试两个消费端
   - 详见 ADR-0003

3. **合并 Blame 热路径调度** (`extension.ts:224-230`) — **已完成（2026-09-07）**
   - 单一定时器 `scheduleLineBlame` 本就是所有 blame 刷新触发点的合并点（自 `64f36fb`），本轮将散落的魔法延迟 `0/150/300` 提取为具名常量：`BLAME_REFRESH_IMMEDIATE_MS`(0) / `BLAME_REFRESH_DEBOUNCE_MS`(150, 默认) / `BLAME_REFRESH_EDIT_DEBOUNCE_MS`(300)，调度策略单一、可独立验证
   - 9 个触发点（编辑器切换、光标移动、文档编辑、仓库/配置变更、初始化）统一经此一处，突发事件合并为至多一次 `refresh()`，避免热路径存在多个挂起定时器
   - 影响：减少不必要的刷新开销（已通过单一定时器防抖实现）

### 中优先级（后续执行）

4. **明确共享类型边界** — **已完成（2026-09-07）**
   - `messages.ts` 已位于 `src/protocol/`，webview 与 extension 两侧均从此导入，消息协议边界本就清晰
   - `layoutCommitGraph.ts` 原处 extension 域的 `src/graph/`（该目录仅此一文件，且为纯函数、无 vscode 依赖），迁入 `src/shared/`（与 `models.ts` 同处，已是 webview↔extension 的规范共享目录）；重指 7 处生产导入（5 处 webview `../../src/shared/...`、2 处 extension `../shared/...`）与 3 处测试导入
   - 显式标注构建边界：共享契约统一落在 `src/shared/`（纯类型/纯函数，webview bundle 可直接依赖，不再越界进入 `src/graph/` 等 extension 域路径）；`layoutCommitGraph.ts` 顶部加注其为共享契约且只依赖 `./models`
   - 影响：架构清晰度提升，避免未来构建问题（webview 打包不再依赖 extension 内部目录）

5. **优化 commitWindow 图重算** (`commitWindow.ts:33-40`) — **已完成（2026-09-07）**
   - `commitWindow.ts` 在窗口淘汰时只重放被淘汰前缀，增量推进 DAG `continuation`；`App.tsx` 将完整图布局缓存纳入 Zustand `WorkbenchState`，普通日志追加页只布局新增尾部，替换/淘汰/筛选/历史模式回退到全量布局
   - 移除渲染期间读写 ref 的缓存方案，避免违反 `react-hooks/refs`；缓存仅存在于 webview UI 状态，不进入扩展端持久化契约
   - 影响：大型仓库连续加载页面时降低 DAG 布局重复计算；输出与从头布局保持一致

6. **改进 LRU 缓存实现** (`GitService.ts:112-142`) — **已完成（2026-09-07）**
   - 抽取通用 `LruCache<K, V>`，以 `Map` 的插入顺序维护最近使用顺序；`get` 与 `set` 均在常数时间内刷新条目，超容量时只淘汰最旧项
   - 文本搜索缓存容量由 2 提升至 4，继续按仓库/过滤条件隔离；`invalidateLogCache(cwd)` 通过快照 key 删除，避免遍历时修改容器
   - 影响：缓存维护逻辑集中、命中热点不再重复编写淘汰代码；额外常驻缓存上限为两个搜索条目，可能增加少量内存占用

7. **拆分 activate 函数** (`extension.ts:62-504`)
   - 拆分为独立初始化模块：`initializeBlameFeature`、`initializeLineEditTracking`、`initializeGitStateWatch`
   - 影响：代码可读性和可维护性提升

8. **改进文件监控错误处理** (`RepositoryWatchManager.ts:51-55`)
   - 对每个 watcher 创建单独 try-catch
   - 影响：单个 watcher 失败不影响其他

### 低优先级（延后执行）

9. **临时文件清理** (`GitService.ts:514-556`)
   - 启动时清理旧的临时目录（使用 `readdir` + 过滤 `git-log-` 前缀）
   - 影响：避免临时文件残留

10. **简化消息验证** (`messages.ts:546-782`)
    - 使用 Zod 等 schema 验证库或提取工厂函数
    - 影响：代码重复度降低

11. **提取布局默认值** (`WorkbenchPanel.ts` + `App.tsx`)
    - 将重复定义的默认值提取到 `models.ts`
    - 影响：维护成本降低

**后果：**

**优点：**
- 启动性能提升（移除立即激活）
- 代码可维护性大幅提升（拆分 God Component）
- 缓存效率提升（改进 LRU 实现）
- 健壮性增强（错误处理改进）

**缺点：**
- 需要重构大量代码（App.tsx 拆分）
- 可能引入回归 bug（需要充分测试）
- 共享类型边界调整需要同步修改构建配置

**迁移说明：**
1. 高优先级优化需要同步更新测试用例
2. App.tsx 拆分需要逐步进行，每步确保功能正常
3. 共享类型边界调整需要更新 esbuild 配置

**未解决风险：**
- App.tsx 拆分可能引入状态管理复杂度
- 增量 checkpoint 实现可能增加内存占用
