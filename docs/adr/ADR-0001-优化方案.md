# ADR-0001: VSCode Git Log 扩展优化方案

**状态：** 已接受
**创建时间：** 2026-09-04
**更新时间：** 2026-09-04

**背景：**

项目分析发现多个可优化点，涵盖性能、代码质量、架构和健壮性。当前扩展使用 `onStartupFinished` 激活策略影响启动性能，App.tsx 单文件过大（~2000行）违反单一职责原则，LRU 缓存实现效率低，文件系统监控缺乏错误处理。

**决策：**

按优先级分阶段实施优化：

### 高优先级（立即执行）

1. **移除 `onStartupFinished` 激活策略** (`package.json:33`)
   - 改为依赖 `onView:gitLogWorkbench.log` 懒加载
   - 影响：所有用户启动时间减少，仅使用 Git Log 时才加载

2. **拆分 App.tsx** (`webview/src/App.tsx`)
   - 提取状态管理到 Context 或 Zustand
   - 拆分为 `CommitLogPanel`、`RefsPanel`、`FilesPanel`、`DetailsPanel` 等独立组件
   - 提取 `useMessageHandler`、`useRequestIdManager` 等自定义 hooks
   - 影响：代码可维护性提升，重渲染范围缩小

3. **合并 Blame 热路径调度** (`extension.ts:224-230`)
   - 合并多次 timer 调度为单次
   - 影响：减少不必要的刷新开销

### 中优先级（后续执行）

4. **明确共享类型边界** (`App.tsx:12-34`)
   - 将 `layoutCommitGraph`、`messages.ts` 等共享代码提取到独立目录
   - 显式标注构建边界
   - 影响：架构清晰度提升，避免未来构建问题

5. **优化 commitWindow 图重算** (`commitWindow.ts:33-40`)
   - 实现增量 checkpoint，避免频繁重算 DAG 布局
   - 影响：大型仓库滚动性能提升

6. **改进 LRU 缓存实现** (`GitService.ts:112-142`)
   - 使用专用 LRU 类或增大缓存容量
   - 缓存 key 使用更高效的序列化方式
   - 影响：缓存命中率提升，减少 GC 压力

7. **拆分 activate 函数** (`extension.ts:62-504`)
   - 拆分为独立初始化模块：`initializeBlameFeature`、`initializeLineEditTracking`、`initializeGitStateWatch`
   - 影响：代码可读性和可维护性提升

8. **改进文件监控错误处理** (`RepositoryWatchManager.ts:51-55`)
   - 对每个 watcher 创建单独 try-catch
   - 影响：单个 watcher 失败不影响其他

### 低优先级（延后执行）

9. **临时文件清理** (`GitService.ts:514-556`)
   - 启动时清理旧的临时目录（使用 `readdir` + 过滤 `git-log-` 前缀）
   - 影响：避免临时文件残留

10. **简化消息验证** (`messages.ts:546-782`)
    - 使用 Zod 等 schema 验证库或提取工厂函数
    - 影响：代码重复度降低

11. **提取布局默认值** (`WorkbenchPanel.ts` + `App.tsx`)
    - 将重复定义的默认值提取到 `models.ts`
    - 影响：维护成本降低

**后果：**

**优点：**
- 启动性能提升（移除立即激活）
- 代码可维护性大幅提升（拆分 God Component）
- 缓存效率提升（改进 LRU 实现）
- 健壮性增强（错误处理改进）

**缺点：**
- 需要重构大量代码（App.tsx 拆分）
- 可能引入回归 bug（需要充分测试）
- 共享类型边界调整需要同步修改构建配置

**迁移说明：**
1. 高优先级优化需要同步更新测试用例
2. App.tsx 拆分需要逐步进行，每步确保功能正常
3. 共享类型边界调整需要更新 esbuild 配置

**未解决风险：**
- App.tsx 拆分可能引入状态管理复杂度
- 增量 checkpoint 实现可能增加内存占用
