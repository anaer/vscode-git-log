# ADR-0001: VSCode Git Log 扩展性能与代码质量优化

**状态：** 已接受
**创建时间：** 2026-09-04

> 当前状态 / 核心结论：本扩展的性能/代码质量/健壮性优化取舍已定并全部落地——仅「移除 `onStartupFinished` 激活策略」一项经评估否决、维持现状；App.tsx 拆分另立 ADR-0003。无需后续动作。

---

## 背景（1-3 句）

项目分析发现多个可优化点，涵盖启动性能、God Component、缓存效率、热路径调度与文件监控健壮性。本篇收敛这些优化的架构取舍；App.tsx 拆分因规模独立，另立 ADR-0003 记录。

## 决策

1. **维持 `onStartupFinished` 激活（否决懒加载）**：原计划改依赖 `onView:gitLogWorkbench.log` 懒加载。否决——当前行 blame 装饰（`currentLineBlame.enabled` 默认 `true`）依赖激活时注册的 `onDidChangeActiveTextEditor`/`onDidChangeTextEditorSelection` 监听，移除后 blame 需首次使用 Git Log 命令才生效，属行为回归。用户确认维持现状。
2. **共享边界与协议归位**：`layoutCommitGraph.ts` 由 extension 域 `src/graph/` 迁入 `src/shared/`（纯函数、无 vscode 依赖，与 `models.ts` 同为 webview↔extension 规范共享目录），重指生产与测试导入；共享契约统一落 `src/shared/`，webview bundle 不再越界进 extension 内部目录。`messages.ts` 位于 `src/protocol/` 作为消息协议边界；重复定义的 `defaultLayout`/`defaultFilters` 提取为单一定义落 `src/protocol/messages.ts`（与类型同处，非 `src/shared/models.ts`——后者不依赖 protocol 方向）。
3. **热路径与渲染性能**：blame 刷新散落的魔法延迟 `0/150/300` 提取为具名常量 `BLAME_REFRESH_IMMEDIATE_MS`/`BLAME_REFRESH_DEBOUNCE_MS`(默认)/`BLAME_REFRESH_EDIT_DEBOUNCE_MS`，9 个触发点统一经单一定时器 `scheduleLineBlame` 合并为至多一次 `refresh()`；`commitWindow` 淘汰时只重放被淘汰前缀、增量推进 DAG `continuation`，完整图布局缓存纳入 Zustand `WorkbenchState`（仅存 webview UI 态、不入扩展端持久化契约），普通追加页只布局新增尾部，替换/淘汰/筛选/历史回退全量；`activate`（~450 行线性脚本）按真实依赖边界拆两段，blame 特性收敛为 `initializeBlameFeature()` 返回 `BlameFeature` 句柄。
4. **缓存与健壮性**：抽取通用 `LruCache<K, V>`（以 `Map` 插入顺序维护、`get`/`set` O(1)、超容量淘汰最旧），文本搜索缓存容量 2→4、按仓库/过滤隔离，`invalidateLogCache(cwd)` 快照 key 删除避免遍历中改容器；`RepositoryWatchManager.replace` 对每个 watcher 单独 try-catch，单个失败仅跳过并 `console.warn`；启动时 `cleanupStaleTemporaryDirectories()` 清理 `git-log-` 前缀陈旧临时目录（`void` 异步不阻塞启动，单点失败不影响其余）。
5. **消息协议精简**：`parseWebviewMessage` 提取 `optionalParentOrOldPath()` 工厂收敛 4 处可选 `parent`/`oldPath` 条件展开；合并 `requestLogPage`/`requestHistoryPage` 与 `ready`/`showOutput` 相同 case 体。
- **不做什么：** 不引入外部 schema 验证库（Zod），不重写竞态逻辑（见 ADR-0003）。

## 后果

- **收益：** 启动/热路径无行为回归前提下减少重复刷新与 DAG 重算；共享契约边界清晰、避免未来 webview 打包越界依赖 extension 内部目录；缓存维护集中、单 watcher 失败隔离。
- **代价 / 权衡：** 文本搜索缓存 +2 条目略增常驻内存；增量布局 checkpoint 略增内存；懒加载否决使启动仍立即激活。
- **未解决风险：** 多窗口同时运行本扩展时，某窗口启动清理可能删另一窗口刚创建的临时目录——生命周期仅单次 diff（毫秒级）、重叠概率极低，接受此风险。

## 实施位置

`package.json`（activation）、`src/extension.ts`（blame 监听注册、`initializeBlameFeature`、`scheduleLineBlame` 与延迟常量）、`src/shared/layoutCommitGraph.ts`、`src/protocol/messages.ts`（协议边界、`defaultLayout`/`defaultFilters`、`optionalParentOrOldPath`）、`src/git/LruCache.ts`+`GitService.ts`、`src/repositories/RepositoryWatchManager.ts`、`webview/src/commitWindow.ts`。
