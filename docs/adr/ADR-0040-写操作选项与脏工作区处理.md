# ADR-0040: 写操作选项与脏工作区处理

**状态：** 提议中
**创建时间：** 2026-11-09

> **当前状态 / 核心结论：** 提案尚未实施。把「脏工作区直接拒绝」改为自动储藏（受 Git 版本约束），并给 Merge 与 Stash 补选项；任何失败路径都必须显式恢复储藏。下一步：确认 autostash 的版本门槛后实施。

---

## 背景

rebase、merge、pull 目前遇到脏工作区一律拒绝，用户需先手动 stash 再重试；Merge 只有单一默认行为；Stash 只能整体储藏，也无法从某个储藏直接开分支。

## 决策

1. **自动储藏**：rebase、merge、pull 在脏工作区改为携带 `--autostash`（`git merge --autostash` 需 Git 2.27+，低于该版本保持现状拒绝并提示）；pull 按其实际策略走 rebase / merge 分支。
2. **失败必须显式恢复**：任何带 autostash 的操作失败后，若 stash 仍存在则提示「改动已保存在 stash」，不得静默丢弃；测试须覆盖「冲突后 stash 仍在」。
3. **Merge 选项**：Merge into Current 改为带选项入口——默认、`--no-ff`、`--squash`、`--no-commit`、自定义消息；默认项与现状行为完全一致。
4. **Stash 增强**：创建时可选仅储藏选中文件（`git stash push -- <paths>`）；新增「Branch from Stash」，执行 `git stash branch <name> <stash>`。
5. **不做什么：** 不做 changelist / shelf 的持久化分组、不做自动提交、不改动现有 stash 的 Apply / Pop / Drop 语义。

## 后果

- **收益：** 常见「先 stash 再 rebase」的两步操作收敛为一步；Merge 与 Stash 能覆盖更多真实场景。
- **代价 / 权衡：** autostash 把「操作前必须干净」的显式约束换成了隐式暂存，用户需理解失败后改动去向。
- **降级方向：** 保守——Git 版本不足时不降级为「强行继续」，仍拒绝并提示手动 stash。
- **未解决风险：** autostash 后若用户手工删除了 stash，失败恢复将无内容可还原；`stash push -- <paths>` 对未跟踪文件不生效。
