# ADR-0012: 支持创建孤儿分支

**状态：** 提议中
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 提议中，尚未实现。决定新增 `createOrphanBranch` 操作，以 `git switch --orphan <name>` 单命令实现「检出并移除全部已跟踪文件」；因该操作会丢弃未提交的已跟踪修改，须走破坏性确认，且**明确不删除未跟踪与忽略文件**。下一步：待批准后实现。

## 背景

现有分支创建只有 `git branch -- <name> <startPoint>`（`src/git/GitOperationService.ts:92-98`），必须指定起点，无法产生无父提交的分支；全仓无 `orphan` / `commit-tree` 相关实现。

实测（git 2.55.0；本扩展声明最低 Git 2.27）：`git switch --orphan <name>` 一条命令即完成「检出 + 移除全部已跟踪文件」，工作区仅剩未跟踪与忽略文件；提交前该分支**无 ref**（`for-each-ref` 与 `git branch` 均不显示），首个提交无 parent 且与既有历史无共同祖先。

## 决策

1. 新增 `createOrphanBranch { name }` 操作，实现为 `git switch --orphan <name>`。**不**采用 `git checkout --orphan` + `git rm -rf -- .` 的两步式：实测前者一步等价，且少一个中途失败的窗口。
2. 语义边界显式声明：本操作只移除**已跟踪文件**，未跟踪与忽略文件保留在工作区。界面文案不使用「清空工作区」这类模糊措辞，改为「移除全部已跟踪文件」。
3. 前置校验：目标分支名已存在时直接拒绝，并把 git 原生的 `a branch named 'x' already exists` 转成结构化提示；存在进行中的 Git 操作（MERGE / CHERRY_PICK / REVERT / rebase / sequencer）时拒绝，复用既有探测逻辑。
4. 破坏性确认走既有 `OperationConfirmation`：文案须列出当前分支名与目标分支名，并说明「未提交的已跟踪修改将无法恢复，未跟踪文件保留」。脏工作区由 git 自身 abort 保护（实测），扩展在其之上给出可读提示，不静默失败。
5. 首次提交前的 UI 说明：该分支此时无 ref，不会出现在 Refs 面板；操作成功提示须明确告知「该分支在首次提交后才会出现在引用树中」，避免用户误判为创建失败。

**不做什么：** 不实现空树提交分支（`commit-tree` + 空树）；不调用 `git clean`，即不删除未跟踪与忽略文件；不自动创建首个提交；不改写任何既有历史。

## 后果

- **收益：** 补齐 GitHub Pages、独立文档分支等场景；单命令完成使失败窗口最小；日志视图已能容忍未出生 HEAD（`src/git/GitService.ts:782-793` 捕获后返回空列表），日志链路无需改动。
- **代价 / 权衡：** 依赖 `git switch`（2.23+），但扩展声明的最低版本 2.27 已覆盖，无兼容性代价。
- **未解决风险：** 首次提交前若用户切走，该分支的创建结果不留任何痕迹（无 ref）——这是 Git 语义固有限制，只能靠成功提示与「首次提交后可见」的说明缓解。

## 验证

已实测（git 2.55.0，临时仓库）：① `git switch --orphan` 后已跟踪文件全部移除且 `status` 干净；② 未跟踪文件保留并显示 `??`；③ 提交前 `for-each-ref refs/heads` 不含新分支，提交后出现；④ 首个提交 `git rev-list --parents -1 HEAD` 无 parent，`git merge-base HEAD main` 无输出；⑤ 脏工作区下该命令 abort 且文件未丢失；⑥ 同名分支存在时报 `a branch named 'x' already exists`；⑦ detached HEAD 下可正常创建。
