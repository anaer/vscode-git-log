# ADR-0012: 支持创建孤儿分支

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 已实现。新增 `createOrphanBranch` 操作，以 `git switch --orphan <name>` 单命令完成「检出并移除全部已跟踪文件」；因丢弃未提交的已跟踪修改走破坏性确认，未跟踪与忽略文件保留；进行中操作与裸仓库由既有通用守卫拦截。下一步：无需后续动作。

## 背景

分支创建此前只有 `git branch -- <name> <startPoint>`（`src/git/GitOperationService.ts#buildOperationArguments` 的 `createBranch` 分支），必须指定起点，无法产生无父提交的分支。实测（git 2.55.0；扩展声明最低 2.27）：`git switch --orphan <name>` 一条命令即完成「检出 + 移除全部已跟踪文件」，工作区仅剩未跟踪与忽略文件；提交前该分支无 ref，首个提交无 parent 且与既有历史无共同祖先。日志查询已能容忍未出生 HEAD（捕获后返回空列表，见 `src/git/GitService.ts`），日志链路无需改动。

## 决策

1. 新增 `createOrphanBranch { name }`，实现为 `git switch --orphan <name>`。不采用 `git checkout --orphan` + `git rm -rf -- .` 两步式：前者一步等价，少一个中途失败窗口。
2. 语义边界显式声明：只移除**已跟踪文件**，未跟踪与忽略文件保留；界面文案用「移除全部已跟踪文件」，不用「清空工作区」这类模糊措辞。
3. 前置校验复用既有通用逻辑：目标分支名已存在时由 git 原生 `a branch named 'x' already exists` 经 `classifyGitError` 透出（与 `createBranch` 同名冲突处理一致，不加专门预检）；存在进行中的 Git 操作（MERGE / CHERRY_PICK / REVERT / rebase / sequencer）时由 `run()` 的操作组守卫统一拒绝，`createOrphanBranch` 不在豁免列表内。
4. 破坏性确认走既有 `OperationConfirmation`：文案列出当前分支（游离 HEAD 时标「the detached HEAD」）与目标分支名，并说明「未提交的已跟踪修改不可恢复、未跟踪文件保留」。脏工作区由 git 自身 abort 保护，扩展在其上给出可读错误。
5. 首次提交前的 UI 说明：命名对话框提示该分支此时无 ref、操作成功提示「首次提交后才出现在引用树」，避免误判创建失败。

**不做什么：** 不实现空树提交分支（`commit-tree` + 空树）；不调用 `git clean`，即不删除未跟踪与忽略文件；不自动创建首个提交；不改写任何既有历史。

## 后果

- **收益：** 补齐 GitHub Pages、独立文档分支等场景；单命令完成使失败窗口最小。
- **代价 / 权衡：** 依赖 `git switch`（2.23+），扩展最低 2.27 已覆盖，无兼容性代价。
- **未解决风险：** 首次提交前若用户切走，该分支不留任何痕迹（无 ref）——Git 语义固有限制，仅靠成功提示与「首次提交后可见」说明缓解。

- 操作契约：`src/protocol/messages.ts#GitOperationRequest`（新增 `createOrphanBranch`）、判别校验 `src/protocol/messages.ts#isGitOperationRequest`（`isGitRefName(name)`）。

## 验证

已实测（真实仓库夹具）：

- 孤儿创建：`createOrphanBranch` 后 `symbolic-ref --short HEAD` 为新分支名，已跟踪 `base.txt` 从工作区移除、未跟踪文件保留；提交前 `for-each-ref refs/heads/<name>` 为空，首次提交后 `rev-list --parents -1 HEAD` 仅含自身（无 parent）。
- 拒绝：同名分支存在时操作被拒且 HEAD 不变；`operationState` 存在时以「in progress」拒绝。
- 确认文案：含当前分支名、目标分支名与「untracked」。
- 协议：合法分支名通过；`-oops`、`a..b`、含换行拒绝。
- 前端：HEAD 菜单出现「Create Orphan Branch…」，对话框含「no parent commit」提示，提交 post `runOperation({kind:'createOrphanBranch', name})`。

测试：`test/unit/GitOperationService.test.ts` +4、`test/unit/protocol.test.ts` +1、`test/unit/WorkbenchApp.test.tsx` 在 HEAD 菜单用例中补孤儿流程断言。全仓 `npm run test:unit` 为 59 个文件、606 通过 / 5 跳过 / 0 失败，`npm run typecheck` 0 报错，`npm run lint` 0 报错。
