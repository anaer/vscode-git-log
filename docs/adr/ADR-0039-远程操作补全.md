# ADR-0039: 远程操作补全

**状态：** 提议中
**创建时间：** 2026-11-09

> **当前状态 / 核心结论：** 提案尚未实施。补齐四块远程能力：推送前预览、后台定时 Fetch（默认关闭，启用时最小 5 分钟）、不签出更新分支、全部仓库批量 Fetch / Update；批量范围已确认为当前工作区已发现的仓库集合。下一步：按已确认范围实施。

---

## 背景

当前 Push 与 Force Push 直接执行，用户看不到将要推送哪些提交；引用面板有 ahead / behind 角标，但没有「只更新这个分支」的路径；后台不会自动感知远程变化，多仓库只能逐个手动 Fetch。

## 决策

1. **推送预览**：Push、Publish、Force Push 前增加确认页，展示待推提交（`git log @{u}..HEAD --oneline`）、文件统计、目标 `remote/branch` 与是否包含标签；列表为空时提示「无可推送内容」并终止，不执行空推送。
2. **后台定时 Fetch**：配置 `gitLogWorkbench.remote.autoFetchMinutes`，默认 0（关闭），启用时最小 5 分钟；默认不自动触网。只 fetch 当前选中的仓库，走现有串行写队列，失败只写输出通道不弹窗，且不打断进行中的前台操作。
3. **不签出更新分支**：非当前本地分支右键「Update to Upstream」，执行 `git fetch <remote> <remoteBranch>:<localBranch>`，非快进即失败且不留中间状态；该分支被其它 worktree 检出时拒绝并指出路径。
4. **批量动作**：工具栏菜单增加「Fetch All Repositories」与「Update All Repositories」，范围限定当前工作区已发现的仓库集合（不含已缓存但工作区已移除的仓库），逐仓库串行执行、逐条报告失败，单个失败不中断其余。
5. **不做什么**：不做后台自动 push、不做定时 pull、不做推送失败自动重试。

## 后果

- **收益：** 推送前可见影响面；多仓库与后台同步不再依赖手工。
- **代价 / 权衡：** 定时 fetch 会周期性触网并可能触发凭据交互，无凭据时只能静默失败；推送多一次确认点击。
- **降级方向：** 宽松——自动 fetch 失败不改变本地状态也不提示，仅记录到输出通道；手动动作失败必须显式报错。
- **未解决风险：** 定时任务与前台操作争用队列时可能推迟刷新；`fetch <src>:<dst>` 在配置了 `push.default` 异常的仓库行为需实测。
