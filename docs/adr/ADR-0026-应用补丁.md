# ADR-0026: 应用补丁

**状态：** 已接受
**创建时间：** 2026-11-05

> **当前状态 / 核心结论：** 新增 Apply Patch：选择 `.patch` / `.diff` → 预览文件与增删行 → `git apply --check` → 应用到工作区；检查失败时可改用 `--3way` 并提示可能留下冲突。已实施并通过验证；下一步：无需后续动作。

---

## 背景

当前扩展只能查看差异，不能把外部补丁带入工作区；补丁导出在既有决策中仍待实现，应用能力与它相互独立。

## 决策

1. **入口与文件**：命令面板 `Git Log: Apply Patch…` 与面板工具栏右键菜单；单文件选择器接受 `.patch` / `.diff`，上限 10 MiB；要求选中的仓库非 bare，且没有进行中的 merge / rebase / cherry-pick / revert。
2. **预览与校验**：用 `git apply --numstat -` 展示文件数、增删行与二进制文件；用 `git apply --check -` 做 dry-run；确认框列出影响范围后再执行。补丁内容经 stdin 传入，不经 shell。
3. **应用目标**：默认只应用到工作区（`git apply -`），不改暂存区、不自动 stash；成功后刷新仓库状态并提示结果，失败交由既有错误分类与下一步提示处理。
4. **三方兜底**：dry-run 失败时提供 `--3way` 选项，并明确提示该模式会写入索引、可能留下冲突；出现冲突后引导到 Source Control 解决，不自动继续。
5. **安全与边界**：依赖 `git apply` 默认拒绝越界路径，并用测试锁定；超大补丁拒绝；本批不做反向应用、部分应用、应用到暂存区、二进制补丁的特殊预览。

## 后果

- **收益：** 外部补丁可在插件内安全落地，与评审/交接场景闭环。
- **代价 / 权衡：** 预览是文件与行数统计而非完整 diff；3-way 会改变索引并可能产生冲突，需要用户后续处理。
- **未解决风险：** 脏工作区导致补丁失败时不会自动 stash；用户需先处理本地改动。二进制补丁按 git 能力原样处理。
