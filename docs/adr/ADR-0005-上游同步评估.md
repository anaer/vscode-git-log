# ADR-0005: 上游 ascenx/vscode-git-log 同步（rebase 控件 + 过滤图折叠）

**状态：** 已接受
**创建时间：** 2026-09-16

> 当前状态 / 核心结论：fork 与上游 merge-base 为 v0.0.9（`64f36fb`），上游 main 至 v0.1.0 的 3 个未并入提交已同步——F1（`d0f0fe6` rebase 续作控件）与 F2（`1951e4c` 过滤图折叠隐藏提交）均已落地并 typecheck+单测+性能验证通过；`2deac97` 发版 chore 与 `dev` 旧线排除。无需后续动作。

**背景：**

本地 `anaer/vscode-git-log`（v0.1.1）fork 自上游 `ascenx/vscode-git-log`。定期跟进上游、评估 v0.0.9 之后的可同步项并落地。

**基线事实：**

- 上游 default 分支 `main` = `2deac97` = tag v0.1.0。`git merge-base HEAD upstream/main` = `64f36fb`（prepare v0.0.9）。本地 HEAD 未含的上游提交恰 3 个：`1951e4c`、`d0f0fe6`、`2deac97`。
- 上游 `dev`（`63c9d61`）与 main 严重分叉（含 v0.0.2–v0.0.8 旧发布），非更新线，持续跟进只认 main。
- fork 的图文件与上游 pre-F2 基线近乎逐字一致（`GitService` 仅差约 40 行、`layoutCommitGraph`/`CommitGraphCell` 仅差数行；fork 把 `src/graph/layoutCommitGraph.ts` 移到 `src/shared/`），故同步以 `git apply -3` 三方合流为主，非手工重写。

## 决策

### 1. 同步项（已落地）

- **F1 rebase 续作控件（`d0f0fe6`）**：新增 `rebaseContinue/rebaseSkip/rebaseAbort` operation、`openSourceControl` 消息、`RepositorySummary.hasUnresolvedConflicts`；fork 现状只有基础 `rebase`，属补齐。
- **F2 过滤图折叠隐藏提交（`1951e4c`）**：`CommitSummary.graphParents/filterMatch` + `layoutCommitGraph` 的 `collapsed` 贯穿线 + `GitService` 文本搜索图拓扑引擎（约 12 个新函数计算被隐藏提交的 graphParents）+ `startRowOffset` 行偏移滚动补偿。

### 2. 排除项

- `2deac97` v0.1.0 发版 chore（版本/CHANGELOG/README/lock）：fork 版本线独立且已到 0.1.1，回并会倒退自身版本与变更日志。
- 上游 `dev` 分支：分叉旧线、特性多已具备，非同步来源。

### 3. 独立决策

- 本批无依赖版本升级，无需另立依赖 ADR。

## 后果

- 收益：补齐 rebase 交互闭环与过滤图渲染正确性两处上游改进。
- 权衡：F1/F2 借上游基线一致性以 `git apply -3` 移植，仅在 fork 分叉点手工合流（见「实施位置」）；未整支 merge、未回退 fork 结构。

## 实施位置

F1（rebase 控件）：`src/protocol/messages.ts`（operation kind + 校验 + `openSourceControl` 消息/解析）、`src/git/GitOperationService.ts`（`buildOperationArguments`/`getOperationConfirmation`/run 守卫——与 fork 既有 `abortCherryPick/abortRevert` 合并、`GIT_EDITOR=true`）、`src/shared/models.ts`（`hasUnresolvedConflicts`）、`src/repositories/discoverRepositories.ts`（`detectUnresolvedConflicts`）、`src/webview/WorkbenchController.ts`+`WorkbenchPanel.ts`（`openSourceControl`→`workbench.view.scm`）、`webview/src/Toolbars.tsx`（表头徽标改为可点按钮、rebase 让位给状态行、`operationStateLabel`）、`webview/src/App.tsx`（log pane `rebase-status-row` + `rebase-active`）、`webview/src/styles.css`。

F2（过滤图折叠）：`src/shared/layoutCommitGraph.ts`（collapsed 线程化，整段照搬）、`src/git/GitService.ts`（graphParents 拓扑引擎，`apply -3`，1 处常量冲突保留 fork `MAX_TEXT_SEARCH_CACHES=4`+新常量）、`src/shared/models.ts`+`src/protocol/messages.ts`（graphParents/filterMatch、`isGraphContinuation` collapsed 校验）、`webview/src/commitWindow.ts`+`CommitGraphCell.tsx`+`CommitList.tsx`（`apply -3` 干净）、`webview/src/styles.css`（1 处 `.commit-subject` flex 冲突取上游 `flex:1`）、`src/webview/WorkbenchController.ts`（`getLog` 批量 `maxGraphRows`/hasMore）；`startRowOffset` 按 fork 拆分结构接线到 `workbenchStore.ts`（state+initial）、`workbenchMessageProcessing.ts`（advanceCommitWindow 入参/回写/两处 reset）、`App.tsx`（滚动锚定 effect + 两处 reset、`previousWindowRowOffsetByRepository`）。测试移植自上游（`graphLayout`/`commitWindow`/`CommitGraphCell`/`GitService`/`protocol`/`WorkbenchController`/`WorkbenchApp`/`graph.performance`），并把上游 `src/graph/` 路径引用改为 fork 的 `src/shared/`。

验证（实测基线）：F1/F2 新增用例均通过（`GitService.test.ts` 的 graphParents 用例、`WorkbenchApp`、`graph.performance` 全过）。当前全仓 `npm run test:unit` 为 59 个文件、554 通过 / 5 跳过 / 0 失败，`tsc --noEmit` 0 报错——单测与类型检查均无既有欠账。未清欠账为 `npm run lint` 的 9 个 `react-hooks/refs` 错误，全部位于未改动的 `webview/src/App.tsx:220-246`。

## 下一步

无需后续动作。上游 main 后续新提交按本方法论（`git apply -3` 为主、分叉点手工合流、逐文件核 fork 现状）另起评估。
