# ADR-0014: 面板内宿主默认右键菜单的处置

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 已实现。webview 在 document 级抑制宿主（Electron / Chromium）默认右键菜单，仅对 `input` / `textarea` / 内容可编辑元素白名单放行，保留输入框内的剪切 / 复制 / 粘贴；已有右键目标的处理器与自定义菜单不变。无需后续动作。

## 背景

用户报告：在扩展面板空白处右键会弹出宿主的剪切 / 复制 / 粘贴菜单，与扩展自有的右键菜单语义冲突。

已核实的代码事实：已有右键目标**都**已调用 `preventDefault()` 抑制默认菜单并改弹自定义菜单——提交行（`webview/src/CommitList.tsx#CommitList`）、引用项（`webview/src/RefsPane.tsx#RefsPane`）、文件项（`webview/src/FilesPane.tsx#FilesPane`）、工具栏（`webview/src/Toolbars.tsx`）。缺口仅在**没有右键处理器的空白 / 背景区域**。全仓无根级 `contextmenu` 监听，`webview/src/index.tsx` 只挂载 `App`。

权衡：全局抑制会连带干掉输入框里的复制粘贴，而面板内有 9 处 `<input>`——含筛选文本、引用搜索（`webview/src/RefsPane.tsx#RefsPane`）、分支名 / 标签名对话框、日期范围选择。粘贴分支名与日期是高频操作，因此必须白名单放行。

## 决策

1. 挂一个 document 级 `contextmenu` 监听统一 `preventDefault()`，抑制宿主默认菜单；落在消息监听 effect 内（与该 effect 的 `addEventListener` 同址安装与清理）。**不放在 `webview/src/index.tsx`**——既有 webview 测试直接渲染 `<App />`、绕过入口文件，放入口会失去测试覆盖。
2. 白名单放行 `input`、`textarea`、内容可编辑元素。判定取 `event.composedPath()[0]` 而非 `event.target`，以兼容 flatpickr 日历等可能的事件重定向。
3. 已有右键目标的处理器保持不变（它们已自行 `preventDefault()` 并弹自定义菜单）；全局监听只补空白区域，不接管已处理区域。
4. 空白区域右键**不弹任何菜单**：既有 `Copy Revision` / `Copy Hash` 等显式动作已覆盖复制需求，不为省一次右键而扩张菜单面。
5. 不改变输入框自身的可选性：不引入 `user-select: none` 的扩大化。

**不做什么：** 不实现自定义的全局右键菜单；不拦截键盘路径（`Ctrl+C` / `Ctrl+V`）；不把抑制逻辑放进 store——属 DOM 关注点，按既有约定留在组件层。

## 后果

- **收益：** 面板内右键行为一致；输入框复制粘贴不受影响。
- **代价 / 权衡：** 白名单按标签名判定，`input[type=checkbox]` 等非文本输入也会被放行，属可接受的过度宽松。
- **未解决风险：** 若宿主后续在 webview 内改用非标准菜单实现，抑制将失效；届时需复查。

## 实施位置

- 白名单判定：`webview/src/App.tsx#keepsHostContextMenu`。
- 监听安装与清理：`webview/src/App.tsx#Workbench` 的消息监听 effect（`suppressHostContextMenu`）。
- 测试：`test/unit/WorkbenchApp.test.tsx` 两条用例，覆盖空白处被抑制、`contextmenu` 在输入框与可编辑元素上放行、卸载后恢复。

## 验证

已实测：① 面板空白（`document.body`）右键 `defaultPrevented === true`；② 引用搜索框与文本筛选框（两个 `type="search"`）右键未被抑制；③ `textarea` 与内容可编辑元素未被抑制；④ 卸载后右键不再被抑制，证明清理生效。

测试注记：jsdom 的 `HTMLElement.isContentEditable` 恒为 `false`（未实现该属性），故内容可编辑分支在用例中改用属性替身断言；真实浏览器不受影响。

全仓 `npm run test:unit` 为 59 个文件、592 通过 / 5 跳过 / 0 失败，`npm run typecheck` 0 报错，`npm run lint` 0 报错（本次移除了 `webview/src/App.tsx` 的 `accumulatedAuthors` 等 ref 读取，此前的 `react-hooks/refs` 告警随之一并消除）。
