# ADR-0013: 发布分支后的远程跟踪引用补齐

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 已实现。`git push --set-upstream` 只写入上游配置，**仅当远程 fetch refspec 覆盖该分支时才创建** `refs/remotes/<remote>/<branch>`；单分支克隆（`--single-branch`）的窄 refspec 因此造成「推送成功、远端有分支、Remote 分组永远为空、点刷新按钮也无效」。修复为发布成功后探测 `%(upstream)`、为空则定向 fetch 物化跟踪引用。残留限制：定向 fetch 不恢复 `%(upstream)`，本地上游标记（ahead / behind / gone）在 refspec 修复前不可用。下一步：无（如需恢复上游标记，须另行同意变更 refspec）。

## 背景

用户报告：对尚无上游的本地分支执行 `Publish Branch` 后，引用面板的 Remote 分组不出现该分支，**点刷新按钮也不出现**。

先按「刷新链路失效」排查，逐环核实后全部排除：控制器确实主动刷新并经 `pendingOperationRefreshGroups` 去重（`src/webview/WorkbenchController.ts#runOperation`）；刷新每次都重跑 `for-each-ref`、引用无缓存（`src/git/GitService.ts#getRefs`）；`refs/remotes/` 前缀被 `classifyRef` 归为 `kind: 'remote'`（`src/git/parsers/parseRefs.ts#classifyRef`）；文件监听已覆盖 `refs/**`、`packed-refs`、`logs/**`（`src/repositories/RepositoryWatchManager.ts`）。结论：**问题不在刷新，而在被读取的引用根本不存在**——刷新有效，只是没有东西可读。

实测（git 2.55.0.windows.3，临时夹具已删除）：`push --set-upstream` 写的是 `branch.<name>.remote` / `.merge` **配置**，跟踪引用是**派生结果**，取决于 fetch refspec 是否覆盖该分支：

| `remote.<remote>.fetch` | 推送后 `refs/remotes/<r>/<b>` | `%(upstream)` |
| --- | --- | --- |
| 默认 `+refs/heads/*:refs/remotes/origin/*` | 创建 | 有 |
| 未设置，或窄 refspec `+refs/heads/main:refs/remotes/origin/main` | **不创建** | 空 |
| 映射到 `refs/remotes/upstream/*` | 创建 | 有 |

refspec 不覆盖该分支时，git 仍打印 `branch 'x' set up to track 'origin/x'`，属**误导性成功提示**，掩盖了引用缺失。用户仓库实测 refspec 为 `+refs/heads/main:refs/remotes/origin/main`（`--single-branch` 克隆的产物），与症状完全吻合。

## 决策

1. `publishBranch` 成功后，若 `%(upstream)` 为空，则执行定向 fetch 物化跟踪引用：`git fetch --no-tags <remote> +refs/heads/<branch>:refs/remotes/<remote>/<branch>`。
2. 该 fetch 只**补齐引用**，不修复配置：不修改 `remote.<remote>.fetch`，不写 `push.autoSetupRemote`，不触碰用户的仓库配置。
3. 补齐失败**不改变操作结果**：推送已成功，失败仅 `console.warn`；分支保持不可见，绝不误报操作失败（操作结果消息不渲染到 UI，无法向用户回传该告警）。
4. `%(upstream)` 非空时直接返回，宽 refspec 的正常路径不产生额外网络往返。
5. 不引入前端乐观插入、引用缓存或独立消息通道；引用仍只来自扩展侧 `for-each-ref` 实时快照。

**不做什么：** 不改写 `remote.<remote>.fetch`；不自动 repair 上游配置；不在前端补一条 ref 掩盖缺失。

## 后果

- **收益：** 单分支 / 窄 refspec 仓库发布分支后，Remote 分组即时出现该分支，无需用户手工 fetch。
- **代价 / 权衡：** 每个「上游为空」的发布多一次定向 fetch（单分支、`--no-tags`）；成功路径无额外开销。
- **未解决风险：** 定向 fetch 不会让 git 推导出上游，`%(upstream)` 仍为空，故本地面板的上游标记（ahead / behind / gone）在 refspec 修复前不可用；修复 refspec 属用户配置变更，须另行同意。

## 实施位置

- 调用点：`src/git/GitOperationService.ts#run`，普通执行分支内 `publishBranch` 成功后。

## 验证

已实测：① 窄 refspec 下发布 `feature` 后 `refs/remotes/origin/feature` 等于 HEAD，远端亦收到该分支；② 注入 fetch 失败时操作仍以成功结果 resolve，远端已收到分支；③ 宽 refspec 下跟踪引用由 push 自身创建，不依赖额外 fetch。
