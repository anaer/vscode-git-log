# ADR-0044: 职责边界：不纳入的能力

**状态：** 已接受
**创建时间：** 2026-11-09

> **当前状态 / 核心结论：** 边界已确认并生效。工作区提交与暂存、三方合并工具、凭据交互、克隆与多仓库标签窗口不纳入本扩展，归 VS Code 原生能力；工作树与子模块管理维持待评估，不另行立项。下一步：无需后续动作。

---

## 背景

对照其他 Git 客户端时，工作区提交、合并工具、凭据对话等能力反复被当作缺口提出。它们与 VS Code 内置能力重叠，实现后会出现两套操作入口与两套冲突处理，与本扩展「Git CLI 为事实源、编辑与 Diff 复用宿主」的原则冲突。

## 决策

1. **工作区提交与暂存不做**：整文件 / hunk / 行级暂存、changelist、shelf 归 VS Code 内置 Source Control。
2. **合并工具与冲突编辑不做**：三方合并归 VS Code 合并编辑器；本扩展只保留中断状态条与冲突计数。
3. **凭据交互不做**：askpass、SSH 密码短语交给 Git 与 VS Code，扩展不保存、不代答。
4. **克隆与多仓库标签窗口不做**：仓库打开与多窗口编排归 VS Code 原生。
5. **待评估项**：工作树与子模块管理暂不纳入，也不另行立项；先核对 VS Code 1.85+ 的原生能力，本 ADR 不为其背书，也不视为缺口；如需纳入须先修订本 ADR。

## 后果

- **收益：** 扩展边界稳定，避免与宿主重复实现导致的状态不一致。
- **代价 / 权衡：** 用户需要在 Git Log 与 Source Control 之间切换；部分用户会认为「功能不全」。
- **不做什么：** 不因对照其他客户端而重新引入上述能力；如需引入须先修订本 ADR。
- **未解决风险：** 宿主能力变化（如 VS Code 新增工作树管理）可能让「待评估项」自然消解，需定期复核。
