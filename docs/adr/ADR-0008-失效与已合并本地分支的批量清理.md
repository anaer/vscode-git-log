# ADR-0008: 失效与已合并本地分支的批量清理

**状态：** 提议中
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 提议中，尚未实现。决定在 Branch 面板新增受控的批量清理入口，判定依据为 `%(upstream:track)` 的 `[gone]` 标记与「已合并入当前分支」两类，且**默认不勾选**未合并分支。下一步：待批准后实现。

## 背景

现有能力只有单分支删除（`src/git/GitOperationService.ts:166-172`，含 force 变体）。`%(upstream:track)` 已被采集（`src/git/GitService.ts:20`），但 `parseTracking` 只提取 ahead/behind 数字、**丢弃 `[gone]` 标记**（`src/git/parsers/parseRefs.ts:36-44`）。结果是「上游远程分支已被删除」的本地分支在界面上完全不可见，也不存在批量清理入口。

## 决策

1. `parseTracking` 扩展为同时返回 `gone` 标记，`RefLabel` 增加对应字段（`src/shared/models.ts`），使「上游已消失」成为可展示状态。
2. 清理候选分两类且**互不合并**：① 上游已消失（`gone`）；② 已合并入当前分支。
3. 「已合并」判定必须显式指定基准分支（`git branch --merged <current>`），不使用裸 `--merged`——后者以当前分支为隐式基准，在错误分支上执行会误删未合并分支。
4. 清理对话框逐条展示候选分支的提交数、最后提交时间、是否为当前分支；默认只勾选 `gone` 分支，未合并分支默认不勾选，需用户显式选择。
5. 复用现有 `OperationConfirmation` 破坏性确认与 `getQueueKey` 队列锁；删除按批执行并逐条汇总成功与失败结果。

**不做什么：** 不实现「一条命令删除所有分支」；不删除当前分支；不删除存在未合并提交且用户未显式勾选的分支；不自动执行清理。

## 后果

- **收益：** 分支清理从 N 次单删降为一次受控批量操作；`gone` 分支此前不可见，现在可被识别与处理。
- **代价 / 权衡：** 批量删除的风险面大于单删，因此默认勾选策略偏保守，用户需要多一次确认动作。
- **未解决风险：** detached HEAD 下「已合并」类判定不可用，需在界面上禁用该类而非回退到隐式基准。

## 实施位置

- 解析：`src/git/parsers/parseRefs.ts` 的 `parseTracking`（当前 `:36-44`）。
- 模型：`src/shared/models.ts` 的 `RefLabel`。
- 采集：`src/git/GitService.ts:20` 的 `REF_FORMAT`（`%(upstream:track)` 已在其中）。
- 操作契约：`src/protocol/messages.ts` 的 `GitOperationRequest` 联合（当前 `:161-189`），新增批量删除请求。
- 执行：`src/git/GitOperationService.ts` 的 `buildOperationArguments` `deleteBranch` 分支（当前 `:166-172`）。
- 前端：`webview/src/RefsPane.tsx` 入口与 `webview/src/Dialogs.tsx` 候选清单对话框。

## 验证

待实现后补：① `gone` 分支被正确识别并与普通分支区分；② 当前分支与未合并分支无法被默认勾选；③ detached HEAD 下「已合并」类被禁用；④ 批量删除后仓库摘要正确刷新且失败项被列出。
