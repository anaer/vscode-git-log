# ADR-0008: 失效与已合并本地分支的批量清理

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 已实现。Branch 面板标题行新增批量清理入口，候选分「上游已消失（`gone`）」与「已合并入当前分支」两类且默认只勾选前者；删除按分支逐条执行并汇总成功与失败。下一步：无需后续动作。

## 背景

批量清理前，能力只有单分支删除（`src/git/GitOperationService.ts#buildOperationArguments` 的 `deleteBranch` 分支）。`%(upstream:track)` 已被采集（`src/git/GitService.ts#REF_FORMAT`），但 `parseTracking` 只提取 ahead/behind 数字、**丢弃 `[gone]` 标记**，结果是「上游远程分支已被删除」的本地分支在界面上完全不可见，也不存在批量清理入口。

## 决策

1. `parseTracking` 扩展为同时返回 `gone` 标记，`RefLabel` 增加对应字段，使「上游已消失」成为可展示状态。
2. 清理候选分两类且**互不合并**：① 上游已消失（`gone`）；② 已合并入当前分支。当前分支与「既非 `gone` 又未合并」的分支不进候选，从入口上杜绝误删。
3. 「已合并」判定必须显式指定基准分支（`git branch --merged=<current>`），不使用裸 `--merged`——后者以 HEAD 为隐式基准，在错误分支上执行会误删未合并分支。游离 HEAD 下没有基准，该类整体禁用，只保留 `gone` 候选。
4. 候选清单逐条展示分支名、`gone` / `merged` 标记、未合并提交数与最后提交时间；**默认只勾选 `gone` 分支**，未合并分支默认不勾选，需用户显式选择。未合并提交数按「当前分支不可达的提交」计（`git rev-list --count <base>..<branch>`），游离 HEAD 下退化为该分支的全部提交。
5. 批量删除请求按分支携带 `force`：未合并的候选走 `-D`，已合并的走 `-d`（后者让 git 在分支于对话框打开后被移动时继续拒绝）。单个分支失败**不中断整批**，按「成功 N 条 / 失败清单」汇总回报，并回传成功删除的 ref 供调用方清理日志过滤器。
6. 复用现有 `OperationConfirmation` 破坏性确认（文案列出分支名与未合并数量）与 `getQueueKey` 队列锁。

**不做什么：** 不实现「一条命令删除所有分支」；不删除当前分支；不自动执行清理；不静默把未合并分支降级为可删除；不为批量删除新建第二条确认路径。

## 后果

- **收益：** 分支清理从 N 次单删降为一次受控批量操作；`gone` 分支此前不可见，现在可被识别与处理。
- **代价 / 权衡：** 批量删除的风险面大于单删，因此默认勾选策略偏保守，用户需要多一次确认动作。
- **未解决风险：** 游离 HEAD 下「已合并」类判定不可用，只保留 `gone` 候选，未提供切换基准分支的入口；未合并候选走 `-D`，若分支在对话框打开后被推进（外部工具新增提交），该提交会一并被删除——确认文案已逐条列出分支名与未合并数量，但未做打开时的 commit 快照比对。

## 验证

实测（真实仓库夹具）：

- 候选筛选：`gone` 分支与其上游被删除后 `%(upstream:track)` 返回 `[gone]`；已合并分支入选；当前分支、未合并且上游正常的分支均不入选；`gone` 分支排在已合并分支之前。
- 游离 HEAD（不传基准）下只剩 `gone` 候选，未合并提交数退化为该分支全部提交数。
- 批量删除：`[已合并(force=false), 未合并(force=false)]` → `Deleted 1 of 2 branches; failed: unmerged-branch (...)`，`deletedRefs` 仅含已删除项；改以 `force=true` 重跑 → `Deleted 1 branch.`。拒绝确认时整批取消且分支保留。
- 协议校验：空数组、非布尔 `force`、`-oops`、`a..b`、重名、超过 100 项一律拒绝。
- 控制器：批量删除后日志过滤器仅保留未删除分支；`requestBranchCleanup` 回传候选清单。
- 前端：`gone` 候选默认勾选、已合并候选默认不勾选；提交时未合并项带 `force: true`、已合并项带 `force: false`。
