# ADR-0030: 身份改写候选与贡献者刷新

**状态：** 已接受
**创建时间：** 2026-11-05

> **当前状态 / 核心结论：** 贡献者列表在操作完成后已随通用刷新重新拉取，并有回归测试固化；Rewrite Author Identity 对话框增加 “Use .mailmap…”，用 `git check-mailmap` 从所选 commits 生成原始身份 → 规范身份候选，选中后填入表单，不自动提交。已实施并通过验证；下一步：无需后续动作。

---

## 背景

ADR-0009 的后续项要求改写后刷新贡献者排序，并基于 `.mailmap` 批量生成身份映射候选。当前操作完成后的通用 `refresh` 会重新执行 `loadRepository`，其中已调用 `getContributors`，因此刷新链路存在但没有回归测试；候选生成与选择器尚不存在。

## 决策

1. **贡献者刷新不新增生产代码**：确认 `runOperation` 成功后的通用 `refresh` 已重新拉取 `getContributors`；补控制器回归测试，防止后续改动移除该行为。
2. **候选生成**：`GitService.getIdentityMappingCandidates` 接收所选 hashes，使用 `git log --no-walk --format=%an%x00%ae` 读取原始身份，再用 `git check-mailmap` 分批解析规范身份；仅返回原始与规范不同的映射，并统计所选 commit 数。
3. **选择器形态**：Rewrite Author Identity 对话框增加 `Use .mailmap…`；宿主拉取候选后用 VS Code QuickPick 展示 `from → to（N commits）`，选中后回填姓名/邮箱，用户仍需手动提交改写。
4. **范围与限制**：仅取当前所选 commits（最多 100）；无候选时显示提示；错误沿用既有错误横幅。不自动提交、不写入 `.mailmap`、不跨仓库扫描。
5. **不做什么**：不实现多组身份一次批量改写，不扩展 `rewriteAuthorIdentity` 的 operation 契约，不自动应用候选。

## 后果

- **收益：** 用户无需手工抄录 mailmap 规范身份；候选来自 Git 自身的 mailmap 解析，覆盖 `.mailmap` 与 `mailmap.file` / `mailmap.blob` 配置。
- **代价 / 权衡：** 一次改写仍只能使用一个身份；所选 commits 若含多个原始身份，选中任一候选会将该身份应用到全部所选 commit（沿用现有对话框语义）。
- **未解决风险：** 无 mailmap 或 mailmap 未覆盖所选身份时无候选；此时用户仍可手工输入。

## 实施位置

- 候选解析：`src/git/GitService.ts#getIdentityMappingCandidates`。
- 协议：`src/protocol/messages.ts` 新增请求 `requestIdentityMappingCandidates` 与回传 `identityMappingSelected`。
- 宿主：`src/webview/WorkbenchController.ts` 处理请求、调用 QuickPick；`src/webview/WorkbenchPanel.ts` 注入 `pickIdentityMapping`。
- 前端：`webview/src/Dialogs.tsx#Dialogs` 的 `Use .mailmap…` 按钮；`webview/src/workbenchMessageProcessing.ts` 回填 `RewriteAuthorIdentityState`。

## 验证

- 单测：真实仓库写入 `.mailmap` 后，候选返回正确的 from/to 与 commitCount；无映射时返回空。
- 控制器：改写操作完成后 `getContributors` 被再次调用，最新 `repositoryData` 携带新贡献者。
- 前端：点击 `Use .mailmap…` 发出 `requestIdentityMappingCandidates`；收到 `identityMappingSelected` 后姓名/邮箱更新。
- 闸门：`npm test` 66 文件、693 通过 / 5 跳过；typecheck、lint、build 通过。
