# ADR-0011: 分支差异结果的导出

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 两档均已实现并通过验证：对比结果可复制全部变更文件路径，也可导出为 `.patch`；**不实现 zip 打包**，以维持零新增运行时依赖。下一步：无需后续动作。

## 背景

扩展已具备 Compare with Current 与 All Changes 多文件对比，但没有把差异结果带出编辑器的能力。「比较两个分支并把变更文件交付给他人」这一场景（评审、交接、对接外部系统）当前无法在本插件内完成，用户只能回到命令行手工拼装管道命令。

## 决策

1. **第一档：复制变更文件路径。** 把当前对比结果的文件路径列表写入系统剪贴板，零依赖、零风险，先行落地。
2. **第二档：导出为补丁文件。** 执行 `git diff <base> <target>` 并把结果写入用户选定路径，扩展名 `.patch`；调用沿用 `GitRunner` 的参数数组方式，**不经过 shell**。
3. 导出内容默认排除二进制文件，与既有 `All Changes` 的排除策略保持一致；导出前提示被排除的文件数量，避免用户误以为导出完整。
4. 导出动作只读取仓库状态，不修改任何工作区或引用。
5. zip 打包不实现：引入 zip 库或调用外部 `zip` / `7z` 均与「Git CLI 为事实源、零新增运行时依赖」的既有基线冲突。

**不做什么：** 不实现 zip / 7z 打包；不实现「导出为目录树快照」；不通过 shell 管道拼装命令；不导出仓库中的二进制文件内容。

## 后果

- **收益：** 补齐对比结果对外交付的路径：复制路径用于评审/脚本，`.patch` 用于交接与跨仓库应用。
- **代价 / 权衡：** `.patch` 对非 Git 用户不如压缩包直观，但更贴近评审与交接的实际用法，且避免了新增依赖。
- **未解决风险：** 导出为单次 `git diff`，stdout 上限设为 32 MiB；超过时由 GitRunner 报错，未实现按文件拆分导出。

## 实施位置

- 对比入口：`src/diff/createComparisonHtml.ts#createComparisonHtml`（Copy Paths 与 Export Patch… 按钮）。
- 复制路径：`src/diff/DiffManager.ts`（`copyComparisonPaths` 消息处理，VS Code `env.clipboard`）。
- 补丁生成与保存：`src/diff/DiffManager.ts#exportComparisonPatch`、`src/git/PatchService.ts#exportDiff`。

## 验证

- 复制路径：`DiffManager` 单测验证全部文件路径（含二进制）去重、排序后写入剪贴板，并提示数量。
- `.patch` 导出：`PatchService` 单测验证导出的 diff 可再次通过 `git apply --check`；`DiffManager` 单测验证按钮消息、路径列表与二进制文件数量提示。
- 闸门：`npm test` 66 文件、689 通过 / 5 跳过；typecheck、lint、build 通过。
