# ADR-0011: 分支差异结果的导出

**状态：** 提议中
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 提议中，尚未实现。决定为既有的分支 / 提交对比结果补齐导出能力，按「复制文件路径」与「导出 `.patch`」两档推进；**不实现 zip 打包**，以维持零新增运行时依赖。下一步：待批准后先落第一档。

## 背景

扩展已具备 Compare with Current 与 All Changes 多文件对比，但没有把差异结果带出编辑器的能力。「比较两个分支并把变更文件交付给他人」这一场景（评审、交接、对接外部系统）当前无法在本插件内完成，用户只能回到命令行手工拼装管道命令。

## 决策

1. **第一档：复制变更文件路径。** 把当前对比结果的文件路径列表写入系统剪贴板，零依赖、零风险，先行落地。
2. **第二档：导出为补丁文件。** 执行 `git diff <base> <target>` 并把结果写入用户选定路径，扩展名 `.patch`；调用沿用 `GitRunner` 的参数数组方式，**不经过 shell**。
3. 导出内容默认排除二进制文件，与既有 `All Changes` 的排除策略保持一致；导出前提示被排除的文件数量，避免用户误以为导出完整。
4. 导出动作只读取仓库状态，不修改任何工作区或引用。
5. zip 打包不实现：引入 zip 库或调用外部 `zip` / `7z` 均与「Git CLI 为事实源、零新增运行时依赖」的既有基线冲突。

**不做什么：** 不实现 zip / 7z 打包；不实现「导出为目录树快照」；不通过 shell 管道拼装命令；不导出仓库中的二进制文件内容。

## 后果

- **收益：** 补齐对比结果对外交付的路径，其中第一档几乎无实现成本。
- **代价 / 权衡：** `.patch` 对非 Git 用户不如压缩包直观，但更贴近评审与交接的实际用法，且避免了新增依赖。
- **未解决风险：** 超大 diff 的输出体积可能触及 `GitRunner` 的 stdout 上限（64 MiB），需在导出前用 `--stat` 预估体量并在超限时提示改用按文件导出。

## 实施位置

- 对比结果来源：`src/editor/EditorFileComparisonCommand.ts` 与 `webview/src/FilesPane.tsx` 的 Compare with Current 入口。
- 剪贴板：VS Code `env.clipboard` API。
- 补丁生成：`src/git/GitRunner.ts` 的参数数组调用（禁止 shell 管道）。
- 保存路径选择：VS Code `window.showSaveDialog`。
- 体积预估：`src/git/GitService.ts` 的 diff 相关查询处。

## 验证

待实现后补：① 复制的路径列表与界面展示一致且顺序稳定；② 生成的 `.patch` 可被 `git apply --check` 通过；③ 二进制文件被排除且提示数量正确；④ 超大体量 diff 触发提示而非静默截断。
