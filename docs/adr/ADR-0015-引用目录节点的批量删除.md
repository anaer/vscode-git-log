# ADR-0015: 引用目录节点的批量删除

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 已实现。Local/Remote/Tag 三个分组的**目录节点**新增右键项，打开可勾选预览对话框（列表取自前端引用快照、默认全不勾、无勾选时禁用删除），一次确认后由新增的跨类型批量操作 `deleteRefs` 逐条删除该目录下的分支/远程分支/标签，扩展侧只弹一次破坏性确认。下一步：无需后续动作。

## 背景

分支树由 `webview/src/buildRefTree.ts#buildRefTree` 按 `/` 分组生成 `directory` 节点（带 `path` 前缀与子叶），此前目录节点没有右键入口——右键菜单只有 `ref`（叶）/`commit`/`file`/`toolbar`/`head`。逐分支删除已有单删与本地批量删（ADR-0008 的 `deleteBranches`），但缺少「删掉整个目录下的所有分支」以及跨远程/标签的批量删除。

## 决策

1. 三类分组的目录节点各新增右键项「删除 `{{path}}/` 下的 {{count}} 项…」；叶 ref、commit、HEAD 右键维持现状。列表已在前端过滤掉当前检出分支与 `*/HEAD` 远程符号引用。
2. 点击打开**可勾选预览对话框**（复用 Branch cleanup 样式 `webview/src/workbenchEffects.ts#BranchCleanupDialogState`、`webview/src/Dialogs.tsx#Dialogs`）：条目取自当前 `state.refs` 快照中该 `path` 下的后代叶节点（`webview/src/RefsPane.tsx#collectFolderLeafRefs`），不额外查询 Git；每条一个勾选框、**默认全部不勾选**，**未勾选任何项时「删除」按钮禁用**；展示 ref 类型与本地 `gone` 标记；标题给出目录前缀。
3. 确认后只发**一个**操作 `deleteRefs { local:[{name,force}], remote:[{remote,branch}], tags:[name] }`，扩展侧只弹**一次**破坏性确认（文案列出各类计数并警告远程条目删除共享远端），逐条执行、单条失败不中断其余、回传成功删除的 ref 供 `src/webview/WorkbenchController.ts#runOperation` 清理日志过滤器（沿用 ADR-0008 的 `deletedRefs`）。
4. 删除语义按类型固定且保守：本地 `git branch -d`（未合并的被 git 逐条拒绝并汇总报告，不强删；`force` 默认 false）；远程 `git push <remote> --delete`；标签 `git tag -d`。名称来源：本地/标签取 `shortName`，远程取 `shortName` 去掉 `<remote>/` 前缀、`remote` 取 `RefLabel.remote`。
5. 复用既有操作组串行守卫与裸仓库只读守卫；`deleteRefs` 的三数组条目总数受批量上限（100）约束，超出即校验拒绝，不静默分批。

**不做什么：** 不新增 Git 查询（列表全部来自前端引用快照）；不删除当前检出分支；不在裸仓库提供入口；不改写历史；不删除目录之外的引用。

## 后果

- **收益：** 「删一个前缀下的所有分支」从逐个右键降为一次可审阅的批量操作，覆盖远程与标签目录。
- **代价 / 权衡：** 远程目录批量删会动共享远端、破坏性高，故强制预览 + 一次显式确认；**默认全部不勾选、须主动选**，避免误删，代价是常规删除多几步勾选。
- **未解决风险：** 前端快照可能落后于实际状态，个别已变动分支的删除会失败并在结果中报告（不静默）；本地 `-d` 一律拒绝未合并分支，需强删者仍走单分支 `Force Delete…`。远程 `git push --delete` 经 `GitRunner` 统一注入 `GIT_TERMINAL_PROMPT=0`，凭证缺失时快速失败、按条目报告，而非在无 TTY 的子进程里卡在终端提示（曾致「Running Git operation…」假死）。

## 验证

已实测：

- 服务（真实仓库夹具）：`deleteRefs {local:[done(-d),dirty(-d)],remote:[origin/to-deploy],tags:[tag-x]}` → `Deleted 3 of 4`，`deletedRefs` 含 `refs/heads/done`/`refs/tags/tag-x`/`refs/remotes/origin/to-deploy`、不含 `refs/heads/dirty`；done 分支与 tag 消失、dirty 保留、远端 `to-deploy` 被 `push --delete` 删除；失败项在 message 中列出且不中断其余。
- 协议：合法混合载荷通过；空载荷（三项皆空）、重名本地项、`-x` 远程、合计 >100 一律拒绝。
- 前端：Local 目录节点 `feature/` 右键出「Delete 2 items in feature/…」，预览框默认 0 选、删除按钮禁用，勾选 `feature/a`/`feature/b` 后提交 post 单个 `deleteRefs {local:[a,b force:false],remote:[],tags:[]}`。

测试：`test/unit/protocol.test.ts` +1、`test/unit/GitOperationService.test.ts` +1、`test/unit/WorkbenchApp.test.tsx` +1。全仓 `npm run test:unit` 为 59 个文件、609 通过 / 5 跳过 / 0 失败，`npm run typecheck` 0 报错，`npm run lint` 0 报错。
