# ADR-0009: 作者身份的识别与历史修正

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 已接受，两层均落地。只读层：`git log` / `git show` / 文件历史改用 `%aN` / `%aE`（mailmap 合并），贡献者列表由 `git shortlog -sne --all` 驱动并随 `repositoryData` 下发。破坏层：`rewriteAuthorIdentity` 复用消息改写闭环（备份分支 + CAS `update-ref`），重写所选 commit 的 `author` / `committer` 行并级联重建受影响后代。

## 背景

User 过滤器为自由文本输入，靠 `--author=<正则>` 匹配（`src/git/logQuery.ts#buildLogArguments`），用户须自行回忆作者姓名或邮箱，全仓无 `shortlog` / `mailmap` 调用。另一方面，批量改写消息的闭环（拓扑重建 + 备份分支 + CAS `update-ref`）已具备，但只重写 commit message、**不触碰 `author` / `committer` 行**，因此错误的提交者信息在当前版本无法修正。

## 决策

1. **贡献者列表**：以 `git shortlog -sne --all` 驱动选择器，展示姓名、邮箱与提交数；点击后写入现有 `authors` 过滤器，不新增过滤器类型与协议消息。
2. **`.mailmap` 只读层**：利用 git 原生 mailmap 支持——提交列表、提交详情与文件历史格式改用 `%aN` / `%aE` 占位符（恒等应用 mailmap），贡献者列表用 `git shortlog -sne --all`（默认应用 mailmap），覆盖仓库 `.mailmap` 及 `mailmap.file` / `mailmap.blob` 配置指向的替代位置与全部语法（含 `Proper Name <proper@email> <commit@email>`、注释行、仅邮箱映射）。该层**不修改任何 Git 对象**，可独立于改写层先行落地。
3. **作者身份改写**：在既有重建闭环中新增 `rewriteAuthorIdentity`，按「旧身份 → 新身份」映射重写 commit 的 `author` 与 `committer` 行，复用同一备份分支约定与 CAS `update-ref` 原子切换。
4. 改写范围与既有消息重写保持一致：目标为当前检出分支 HEAD、选定 commit 须在该分支可达、支持任意多选（不要求连续）、按拓扑序重建。
5. `.mailmap` 语法须覆盖 `Proper Name <proper@email> <commit@email>` 形式（含注释行与仅邮箱映射），否则会出现错误合并。

**不做什么：** 不引入 `git filter-repo` 或任何 Python 运行时；不保留 GPG / mergetag 签名（沿用既有剥离策略）；`.mailmap` 层不做任何写操作；不实现跨分支批量改写。

## 后果

- **收益：** 作者身份修正在只读层零风险可用；破坏层复用已建成的安全闭环，边际实现成本显著低于新建工具。
- **代价 / 权衡：** 改写 `author` 会改变全部受影响 commit 的 oid，破坏性与消息改写同级，必须同样走破坏性确认。
- **未解决风险：** `.mailmap` 的姓名与邮箱映射可能一对多，合并显示需定义确定性优先级，否则同一作者在不同视图下显示不一致。

## 实施位置

- 贡献者枚举：`src/git/GitService.ts#getContributors`（`git shortlog -sne --all`）；随 `repositoryData` 消息下发（`src/webview/WorkbenchController.ts#loadRepository`）；前端 User 过滤弹层由 `webview/src/App.tsx` 的 `authorFilterOptions` 消费。
- mailmap 合并：`git log` / `git show` 改用 `%aN` / `%aE`（`src/git/GitService.ts` 的 `LOG_FORMAT` / `DETAILS_FORMAT`、`src/git/FileHistoryService.ts` 的 `FILE_HISTORY_FORMAT`），消费点为提交列表、提交详情与文件历史；无需自写解析器。
- 重写闭环：`src/git/GitOperationService.ts` 的 `planCommitPatch` / `patchCommitObjects` / `applyCommitPatch`（由既有 `planMessageRewrite` / `patchMessageRewrite` / `rewriteCommitMessages` 泛化而来，消息改写与身份改写共用：`messageEdits` / `identityEdits` 双映射、拓扑重建、备份分支、CAS `update-ref`；身份分支在重建 commit 对象时改写 `author` / `committer` 行的姓名与邮箱、保留时间戳）。
- 操作契约：`src/protocol/messages.ts` 的 `GitOperationRequest` 联合新增 `rewriteAuthorIdentity { hashes, name, email }`；确认对话框与前端入口位于 `webview/src/ContextMenu.tsx` / `webview/src/Dialogs.tsx`。

## 验证

- 只读层已实测（`test/unit/GitService.test.ts`）：① `git shortlog -sne --all` 聚合姓名 / 邮箱 / 提交数；② 写 `.mailmap` 后 shortlog 与 `git log` 均合并身份别名。
- 破坏层已实测（`test/unit/GitOperationService.test.ts`）：③ 改写后受影响 commit 的 `author` / `committer` 变为新身份且 oid 变化、作者时间戳保留；④ 备份分支（`identity-rewrite-backup/*`）指向改写前 tip；⑤ 非目标祖先 commit 的 oid 不变、后代 commit 保持自身身份；⑥ 目标不可达、确认期间分支变动均被拒绝且不留备份分支。
