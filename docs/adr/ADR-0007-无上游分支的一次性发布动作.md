# ADR-0007: 无上游分支的一次性发布动作

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 已实现。`publishBranch` 在检测到当前分支无上游时，以 `git push --set-upstream <remote> <branch>` 完成一次性发布，只写入本分支的上游绑定、不改写 `push.autoSetupRemote`。下一步：`push.default=matching` 下普通 Push 对无上游分支静默假成功，需单独立项。

## 背景

普通推送走裸 `git push`（`src/git/GitOperationService.ts#buildOperationArguments` 的 `push` 分支），而 `push.autoSetupRemote` 只在**强推目标解析**路径里被读取（`src/git/GitOperationService.ts#resolvePushPlan`）。因此新建分支首次推送时，扩展只能把 git 的原生报错透传给用户，自身不提供发布入口。

该失败路径取决于用户的 `push.autoSetupRemote`：未开启时（git 默认）裸 `git push` 报 `no upstream branch` 并中断；已开启时 git 自行建立上游，本动作退化为冗余但无害。`push.default=matching` 时是更差的形态——裸 `git push` 输出 `Everything up-to-date` 后**静默不推送**。

## 决策

1. 推送前检测当前分支的上游配置：`branch.<name>.remote` 与 `branch.<name>.merge` 齐全时拒绝并指向 Push，仅存在一项时按「上游配置不完整」拒绝。
2. 无上游且远程可唯一解析时，以「发布分支」语义执行 `git push --set-upstream <remote> <branch>`；远程解析复用 `src/git/GitOperationService.ts#readConfig` / `src/git/GitOperationService.ts#readAllConfig`，不重复实现。
3. 远程按 `branch.<name>.pushRemote` → `remote.pushDefault` → **唯一远程** 解析；多远程且无前两者时不猜测、**不回落 `origin`**，直接拒绝。
4. 该动作只对本次推送生效：仅写入当前分支的上游绑定（`branch.<name>.remote` / `branch.<name>.merge`），不改写 `push.autoSetupRemote` 或任何其他配置，可用 `git branch --unset-upstream` 撤销。
5. 其余边界一律拒绝并给出可读文案，不把 git 原文透传：分支尚无提交（`src refspec does not match any`）、游离 HEAD、`remote.<name>.mirror=true`（`--mirror can't be combined with refspecs`）、远程为 `.`。

**不做什么：** 不改写用户全局或仓库级 `push.autoSetupRemote`；不为多远程仓库自动挑选远程；不检查 `push.default`（命令行显式 refspec 使其完全不参与，实测 `matching` / `nothing` 下均正常推送）；不把「发布分支」并入既有 force-push 目标解析路径；不提供取消 / 重绑上游的动作；不处理 `[gone]` 分支（属 ADR-0008）；不额外处理远程侧失败（无权限 / 分支被保护），仍走既有 `classifyGitError`。

## 后果

- **收益：** 无上游分支的首次推送从「报错中断」或「静默假成功」变为可完成动作。
- **权衡：** 与 git 原生 `push.autoSetupRemote=true` 语义重叠，但本方案不改配置、默认更保守，两者可共存。
- **未解决风险：** 前端 refs 快照过期时仍会落到普通 Push 并失败，未提供错误横幅的一键恢复入口。

## 实施位置

- 操作契约：`src/protocol/messages.ts#GitOperationRequest` 新增 `publishBranch` 成员，判别校验 `src/protocol/messages.ts#isGitOperationRequest`。
- 发布解析：`src/git/GitOperationService.ts#resolvePublishPlan`。
- 配置读取：`src/git/GitOperationService.ts#readConfig` / `src/git/GitOperationService.ts#readAllConfig`，由 `resolvePushPlan` 与 `resolvePublishPlan` 共用。
- 参数构造：`src/git/GitOperationService.ts#buildOperationArguments`（`publishBranch` case）。
- 执行回填：`src/git/GitOperationService.ts#run`（`publishBranch` 分支）。
- 前端入口：`webview/src/App.tsx#Workbench` 计算 `currentBranchHasUpstream` 并传入 `ContextMenu`；`webview/src/ContextMenu.tsx#ContextMenu` 据 `toolbarPublishesBranch`（工具栏菜单）与 `refPublishesBranch`（分支右键菜单）在「Push」与「Publish Branch」之间切换。

## 验证

已实现并实测：① 无上游分支发布成功，远端出现同名分支且与本地 HEAD 一致，`branch.<name>.remote` / `.merge` 被建立；② 多远程且无 `pushRemote` / `remote.pushDefault` 时拒绝，两远端 refs 零变化；③ 已有上游、上游配置不完整、未出生分支、游离 HEAD、mirror 远程均被拒绝；④ 发布前后 `push.autoSetupRemote` 取值不变，且未被写入仓库级配置；⑤ `push.default` 为 `matching` / `nothing` 时仍发布成功；⑥ `remote.<name>.push` 的自定义 refspec 被命令行 refspec 覆盖。

测试：`test/unit/GitOperationService.test.ts` 新增 14 项、`test/unit/protocol.test.ts` 新增 1 项、`test/unit/WorkbenchApp.test.tsx` 新增 1 项。全仓 `npm run test:unit` 为 59 个文件、592 通过 / 5 跳过 / 0 失败，`npm run typecheck` 0 报错，`npm run lint` 0 报错（本次移除了 `webview/src/App.tsx` 的 `accumulatedAuthors` 等 ref 读取，此前的 `react-hooks/refs` 告警随之一并消除）。用户可见的菜单表已同步到 `README.md` 与 `README.zh-CN.md`。
