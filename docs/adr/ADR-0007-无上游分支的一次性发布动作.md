# ADR-0007: 无上游分支的一次性发布动作

**状态：** 提议中
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 提议中，尚未实现。决定在推送路径补齐「本地分支无上游」的检测与一次性发布动作（语义等价 `git push --set-upstream <remote> <branch>`），且**不**改写用户任何层级的 `push.autoSetupRemote` 配置。下一步：待批准后实现。

## 背景

普通推送走裸 `git push`（`src/git/GitOperationService.ts:141`），而 `push.autoSetupRemote` 只在**强推目标解析**路径里被读取（`src/git/GitOperationService.ts:418`）。因此新建分支首次推送时，扩展只能把 git 的原生报错透传给用户，自身不提供发布入口——这是本插件最常见的推送失败场景。

## 决策

1. 推送前检测当前分支是否已建立上游，即 `branch.<name>.remote` 与 `branch.<name>.merge` 是否同时存在。
2. 无上游且远程可唯一解析时，以「发布分支」语义执行 `git push --set-upstream <remote> <branch>`，远程解析复用现有 `resolvePushPlan`（`src/git/GitOperationService.ts:363-465`）的 `readConfig` / `readAllConfig` 逻辑，不重复实现。
3. 远程无法唯一解析（多远程且无 `remote.pushDefault` / `branch.<name>.pushRemote`）时不做猜测，提示用户先显式配置推送远程。
4. 该动作只对本次推送生效，不写入任何 git 配置。
5. 检测到 `push.default` 为 `matching` 或 `nothing` 时直接拒绝并说明原因，不静默覆盖 git 语义。

**不做什么：** 不改写用户全局或仓库级 `push.autoSetupRemote`；不为多远程仓库自动挑选远程；不把「发布分支」合并进既有 force-push 目标解析路径。

## 后果

- **收益：** 新分支首次推送从「报错中断」变为可完成动作，消除扩展内最常见的推送失败路径。
- **权衡：** 与 git 原生 `push.autoSetupRemote=true` 存在语义重叠，但本方案不改配置、默认更保守，两者可共存。
- **未解决风险：** 远程推送失败（无权限、分支被保护）仍需依赖既有 `classifyGitError` 归类提示，本动作不额外处理。

## 实施位置

- 推送目标解析：`src/git/GitOperationService.ts` 的 `resolvePushPlan`（当前 `:363-465`）。
- 操作契约：`src/protocol/messages.ts` 的 `GitOperationRequest` 联合（当前 `:161-189`），新增 `publishBranch` 成员。
- 参数构造：`src/git/GitOperationService.ts` 的 `buildOperationArguments` `push` 分支（当前 `:129-141`）。
- 前端入口：`webview/src/Toolbars.tsx` 推送动作，在检测到无上游时改为「发布分支」提示。
