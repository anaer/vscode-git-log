# ADR-0037: 历史改写的安全护栏与增量动作

**状态：** 提议中
**创建时间：** 2026-11-09

> **当前状态 / 核心结论：** 提案尚未实施。为已推送历史加默认拦截（受保护分支 + 改写前逐条列明已推送提交），并补两个高频增量动作：撤销上一次提交、Fixup into Parent；已确认未推送 HEAD 的 Amend 不受拦截。下一步：按已确认口径实施。

---

## 背景

扩展已支持 drop、squash、批量改信息、force-with-lease 等改写与强推动作，但没有任何分支级保护：`main` / `master` 与已推送提交同样可以被改写。同时缺两个日常动作：撤销刚提交但未推送的一次提交、把修补并入父提交。

## 决策

1. **受保护分支**：配置 `gitLogWorkbench.history.protectedBranches`（默认 `main`、`master`）；在其上拒绝 Force Push with Lease 与一切改写**已推送**提交的动作（drop / squash / edit messages / fixup / undo），提示改用新分支；不提供一次性覆盖开关。未推送 HEAD 的 Amend 不受本条拦截，沿用现有 Amend 入口；Force Push with Lease 是唯一按分支名无条件拒绝的动作。
2. **已推送改写警告**：非受保护分支上，目标区间已被上游包含时，确认框逐条列出「将改写 N 条已推送提交」及对应分支名。
3. **Undo Last Commit**：执行 `git reset --soft HEAD^`，保留索引与工作区；本扩展没有提交输入框，原提交消息改为复制到剪贴板并在通知中展示。HEAD 已推送时入口不可用。
4. **Fixup into Parent**：把选中提交并入父提交且沿用父提交消息（区别于 Squash 需输入新消息），复用现有提交对象重建、备份分支与 CAS 切换闭环。
5. **不做什么**：不做交互式变基（见 ADR-0041）；不做 reflog 浏览器式的通用后悔药。

## 后果

- **收益：** 误操作强推与误改已推送历史有了默认拦截，且拦截理由可读。
- **代价 / 权衡：** 受保护分支上无法用扩展整理历史，必须新建分支；个人仓库会感到多余摩擦，故用配置项放开。
- **降级方向：** 保守——判定不出是否已推送时按「已推送」处理并要求确认。
- **未解决风险：** 未 fetch 的仓库用 `git branch -r --contains` 可能漏判推送状态；配置为空的受保护分支列表等于关闭全部拦截。
