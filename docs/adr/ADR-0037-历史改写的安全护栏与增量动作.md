# ADR-0037: 历史改写的安全护栏与增量动作

**状态：** 提议中
**创建时间：** 2026-11-09

> **当前状态 / 核心结论：** 护栏、撤销上一次提交与 Fixup into Parent 已实现；Undo 独立拒绝已推送或状态不明的 HEAD，Fixup 复用对象重建、备份分支与 CAS。下一步：完成最终全量回归后定稿。

---

## 背景

Drop、Squash、批量改消息与强推会改变共享历史，需要分支级保护和明确的已推送范围提示。日常整理还需要撤销未推送的最后一次提交，以及保留父提交消息的并入操作。

## 决策

1. **受保护分支**：配置 `gitLogWorkbench.history.protectedBranches`，默认 `main`、`master`；拒绝 Force Push with Lease 与改写已推送提交，不提供一次性覆盖开关。Force Push with Lease 按分支名无条件拦截；Amend 沿用现有独立入口，未推送 HEAD 的 Amend 不受本护栏拦截。
2. **已推送改写警告**：非受保护分支上的改写先列出已推送数量、逐条提交及对应远程分支。Fixup 判定范围包含父提交、选中提交与全部受影响后继；确认后和引用更新前复验，推送范围或分支证据扩大时拒绝执行并要求重新确认。
3. **Undo Last Commit**：只接受当前检出分支、存在父提交且确认未推送的 HEAD；已推送或推送状态不明时一律拒绝，清空保护分支配置也不例外。确认前保存 HEAD、分支与消息，执行前复验操作状态和推送状态，再软重置到记录的第一父提交；索引、工作区和未跟踪文件不变。原消息去掉一个结尾换行后通过剪贴板和宿主通知展示；复制失败显示完整原文，通知失败不把已完成 Git 操作报成可重试失败。
4. **Fixup into Parent**：只接受当前分支第一父链上有父提交的单个非合并提交，拒绝父提交或后继路径中的合并；允许并入根提交，但不可选择根提交。以子提交树重建父对象，保留父消息及作者、提交者信息；子提交映射到新父对象，后继只更新父引用、不改文件树，沿用签名剥离规则。先建备份分支，再以期望旧 HEAD 做 CAS 更新；保留脏索引和工作区。
5. **共同边界**：复用仓库操作队列、破坏性确认及浅克隆、冲突、进行中操作、其他 worktree 检出同分支的检查；确认期间分支或 HEAD 变化即拒绝，取消不写对象或引用。不做交互式变基（见 ADR-0041），不做 reflog 浏览器式通用恢复入口。

## 后果

- **收益：** 未推送历史可整理，共享历史有默认拦截和逐条风险提示；Fixup 失败仍保留原分支或备份。
- **代价 / 权衡：** 受保护分支只能整理未推送历史；清空配置解除分支保护，但不解除 Undo 的独立限制。对象重建改变提交哈希并移除失效签名。
- **降级方向：** 远程判定失败视为全部已推送；Undo 和受保护分支拒绝执行，非受保护分支的 Fixup 须确认整个受影响范围。
- **未解决风险：** 推送判断只依赖本地远程跟踪引用，未 fetch 或引用未物化时可能漏判。外部 Git 进程不受扩展队列约束；Undo 的最终检查与 soft reset 不是原子事务，Fixup 的 CAS 也不锁定远程引用或外部检出操作。
