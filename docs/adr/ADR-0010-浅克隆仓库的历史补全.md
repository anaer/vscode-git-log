# ADR-0010: 浅克隆仓库的历史补全

**状态：** 已接受
**创建时间：** 2026-09-17

> **当前状态 / 核心结论：** 已实现。仓库摘要新增 `isShallow`，浅克隆在提交区顶部显示「历史被截断」提示并提供就地「Fetch full history」动作（`git fetch --unshallow <remote>`）；对 `--single-branch` 窄 refspec，补全时把 `remote.<name>.fetch` 扩展为通配 refspec（在确认对话框逐字列出后再写）。历史重写前的浅克隆拒绝语义保留为兜底。下一步：无需后续动作。

## 背景

历史重写前会探测浅克隆并直接抛错「A complete clone is required; this repository is shallow.」（`src/git/GitOperationService.ts#assertCommitPatchStillCurrent`），界面既无感知也无恢复路径。同时普通 `fetch` 走 `--all --prune`（`src/git/GitOperationService.ts#buildOperationArguments` 的 `fetch` 分支），而单分支浅克隆的 `remote.<name>.fetch` 只覆盖一个分支，Fetch 拉不到其他分支——这正是「`--depth=1` 后取不到其他分支」的成因。

## 决策

1. 浅克隆探测落到仓库摘要采集：`inspectRepository` 在既有 `rev-parse` 批调用里加 `--is-shallow-repository`，`RepositorySummary` 增加 `isShallow`，使界面可感知该状态。
2. 提交区顶部在 `isShallow` 为真且非裸仓库时显示「历史被截断」提示，避免用户把截断历史误认为完整历史。
3. 新增 `fetchFullHistory` 动作执行 `git fetch --unshallow <remote>`；远程按 `branch.<name>.remote` → `remote.pushDefault` → 唯一远程解析，多远程且无前两者时不猜测、直接拒绝。访问远程、体积可能很大，须先确认。
4. 对窄 refspec，补全动作把 `remote.<name>.fetch` 扩展为通配 `+refs/heads/*:refs/remotes/<remote>/*`；该配置变更在确认对话框中逐字列出后再执行，不静默写入。窄 refspec 判定：已配置 fetch refspec 且其左端不含 `*`（不覆盖全部分支）。
5. 补全完成后经既有刷新链路重取仓库摘要清除提示；refspec 扩展与后续 fetch 是尽力而为——`--unshallow` 成功后其失败只 `console.warn`，不误报整体操作失败（历史已恢复）。原「历史重写要求完整克隆」的拒绝语义保留为兜底。

**不做什么：** 不静默改写 `remote.<name>.fetch`；不在裸仓库上提供该动作；不自动触发 `--unshallow`；不在重写守卫里去掉浅克隆兜底。

## 后果

- **收益：** 「历史重写不可用」的死胡同错误变为可执行的恢复动作；顺带修复浅克隆下其他分支不可见的问题。
- **代价 / 权衡：** `--unshallow` 下载完整历史，大仓库耗时与体积显著，因此必须显式确认；界面不无脑展示该动作（仅浅克隆可见）。
- **不做什么（残留）：** 若远程不可达，动作失败仍走既有 `classifyGitError`；未对「已浅但用户想保持浅」提供偏好开关。

## 实施位置

- 摘要模型：`src/shared/models.ts#RepositorySummary`（新增 `isShallow`）。
- 采集：`src/repositories/discoverRepositories.ts#inspectRepository`（`rev-parse --is-shallow-repository`）。
- 操作契约：`src/protocol/messages.ts#GitOperationRequest`（新增 `fetchFullHistory`，含内部回填的 `remote` / `refspecFrom` / `refspecTo`）、判别校验 `src/protocol/messages.ts#isGitOperationRequest`、`src/protocol/messages.ts#isRefspecDisplay`。
- 远程与 refspec 规划：`src/git/GitOperationService.ts#planFullHistory`（复用 `src/git/GitOperationService.ts#readConfig` / `src/git/GitOperationService.ts#readAllConfig`）。
- 参数构造：`src/git/GitOperationService.ts#buildOperationArguments`（`fetchFullHistory` → `['fetch','--unshallow',remote]`）。

- 前端：`webview/src/App.tsx#Workbench` 的截断提示条与「Fetch full history」按钮。

## 验证

已实测（真实浅克隆夹具，`init` + `fetch --depth 1` 构造，本地 `git clone --depth` 会被 git 本地优化绕过故不采用）：

- 摘要采集：浅克隆 `inspectRepository` 得 `isShallow: true`，完整仓库该字段缺省。
- 恢复动作：单分支浅窄克隆经 `fetchFullHistory` 后 `rev-parse --is-shallow-repository` 转 `false`、`rev-list --count HEAD` 由 1 增至全部、`remote.origin.fetch` 变通配、`refs/remotes/origin/other` 出现。
- 守卫：缺确认时拒绝、无远程时拒绝、`buildOperationArguments` 在未解析远程时抛错、确认文案含 `refspecFrom`/`refspecTo` 逐字串。
- 协议：仅 `kind` 可过校验；`-x` 远程、含换行或超长的 refspec 一律拒绝。
- 前端：浅克隆显示提示条并 post `runOperation({kind:'fetchFullHistory'})`；完整克隆不显示。
