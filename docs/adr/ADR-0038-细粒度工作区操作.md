# ADR-0038: 细粒度工作区操作

**状态：** 提议中
**创建时间：** 2026-11-09

> **当前状态 / 核心结论：** 提案尚未实施。支持把某个提交里的文件或目录单独摘取到工作区、把文件恢复到任意修订，并补 .gitignore 与定位两项低风险动作；依赖 `git restore --source`，要求 Git 2.23+。下一步：确认路径范围后实施。

---

## 背景

目前只能整提交 cherry-pick / revert，或把文件打开为只读的历史版本；用户若只想搬运一次提交里的一个文件，只能回到命令行。变更文件右键也缺「加入 .gitignore」这类高频小动作。

## 决策

1. **版本门槛**：部分摘取、部分还原与单文件恢复统一使用 `git restore --source`，要求 Git 2.23+；低于该版本隐藏全部入口，沿用现有能力集机制。
2. **部分摘取 / 部分还原**：在提交的 Changed Files 中选中文件或目录——摘取为 `git restore --source=<commit> --worktree --staged -- <pathspec…>`，还原为同命令换 `--source=<commit>^`；目录按 pathspec 一次调用，不逐文件循环；根提交没有父版本，还原入口隐藏。
3. **单文件从修订恢复**：Changed File 与文件历史右键增加「Restore from This Revision」，语义与决策 2 的摘取相同，只接受单路径。
4. **两个低风险动作**：Changed File 右键增加「Add to .gitignore」（只追加尚不存在的模式，写入前预览）与「Reveal in Explorer」。
5. **不做什么**：不做 hunk 或行级暂存、不做变更列表分组（归 VS Code SCM）；不自动提交。

## 后果

- **收益：** 单文件搬运与回滚不再需要离开编辑器。
- **代价 / 权衡：** 命令直接写 index，用户已暂存的其它改动会混入同一次提交——确认框必须逐条列出目标路径。
- **降级方向：** 保守——Git 版本不足时隐藏入口，不用 `git checkout <rev> -- <path>` 近似替代（该写法对「源版本不存在该路径」会报错）。
- **未解决风险：** 路径重命名后按当前路径执行 `restore --source` 可能取不到内容，需在失败时给出可读提示。
