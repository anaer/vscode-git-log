# ADR-0004: 工作区面板默认尺寸取 UI 可拖下限

**状态：** 已接受
**创建时间：** 2026-09-16

> 当前状态 / 核心结论：Commit Details 面板默认高度与 Branches(refs) 面板默认宽度一律取各自「UI 可拖拽最小值」而非协议校验 floor，新状态下面板以最紧凑尺寸展开。已落地 detailsHeight=100、refsWidth=160。

**背景：**

`defaultLayout` 原把 `detailsHeight` 设为 156、`refsWidth` 设为 220，首屏占用垂直/水平空间过多，压缩主提交列表可见区。需求是两类面板默认「显示为最小尺寸」。

**决策：**

1. 默认值取 UI 可拖下限，不取协议 floor：`detailsHeight` 可拖下限 100（`App.tsx` resize `min` 与 resizer `aria-valuemin`），协议 floor 为 80；`refsWidth` 可拖下限 160，协议 floor 为 120。取 floor 会让默认值低于用户能拖到的尺寸，产生不一致。协议 `inRange` 范围保持不动，仅作宽松兜底。
2. 两处默认常量同步：`src/protocol/messages.ts` 的 `defaultLayout`（webview 经 `workbenchStore.ts` 复用）与 `src/webview/WorkbenchPanel.ts` 的 `DEFAULT_LAYOUT`（扩展进程落盘布局兜底）。

**不做什么：** 不改各面板拖拽 `min`、不改协议 `inRange` 校验范围、不改测试 fixture 中的 `220`/`156`（其为显式输入值，非默认常量断言）。

**实施位置：** `messages.ts` / `WorkbenchPanel.ts` 的 `refsWidth`、`detailsHeight`。

## 下一步

无需后续动作（`filesWidth` 等其它面板如需同款处理再议）。
