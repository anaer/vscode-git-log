# ADR-0017: 右键菜单命名规范约定

**状态：** 已接受
**创建时间：** 2026-09-18

> 当前状态 / 核心结论：统一右键菜单命名规范——建分支/标签统一 Create、复制 hash 统一 Copy Hash、Reset 系列统一 `Reset Current Branch (mode)` 格式、rebase 统一 `Rebase Current onto This`、commits 用 Title Case，并固化省略号与禁用态 title 约定。已实施并通过验证。无需后续动作。

---

## 背景（1-3 句）

右键菜单（`ContextMenu.tsx`）存在同一动作跨菜单命名漂移：New Branch / Create Branch / New Branch from 并存，Copy Hash 与 Copy Revision 并存，Reset 两种格式并存，rebase 文案两种并存。省略号与禁用态 title 约定整体一致，需要固化为规范。

## 决策

1. **建分支/建标签统一 `Create`**：commit 菜单 `New Branch…`/`New Tag…` 改为 `Create Branch…`/`Create Tag…`，与 head 菜单一致；ref 菜单 `New Branch from…` 改为 `Create Branch from…`（统一动词，保留来源语义后缀）。
2. **复制 hash 统一 `Copy Hash`**：head 菜单 `Copy Revision` 改为 `Copy Hash`，与 commit 菜单一致。
3. **Reset 系列统一 `Reset Current Branch (mode)` 格式**：commit 菜单 `Soft Reset`/`Mixed Reset`/`Hard Reset…` 改为 `Reset Current Branch (soft)`/`(mixed)`/`(hard)…`，与 head 菜单一致。
4. **rebase 文案统一带目标**：ref 菜单 `Rebase Current onto` 改为 `Rebase Current onto This`，与 commit 菜单一致。
5. **commits 用 Title Case**：commit 菜单 `Drop commits…`/`Squash commits…` 改为 `Drop Commits…`/`Squash Commits…`，与 `Edit Commit Messages…`/`Copy Full Message` 一致。
6. **命名规范固化**：① 弹确认框或需输入的操作以 `…` 结尾（与 GitOperationService 确认清单一致）；② 禁用态一律提供 `title` 说明原因；③ 菜单文本用「动词 + 宾语」结构，宾语优先用常见词（Commit/Hash）而非 git 术语（Revision/Identity 可接受）；④ 命令式菜单标题遵循 Title Case。

## 后果

- **收益：** 同一动作跨菜单单一命名，用户不再混淆；reset 三种模式在任意入口观感一致。
- **代价 / 权衡：** `Rebase Current onto This` 在 ref 菜单中 "This" 指右键的 ref，语义依赖上下文，但可接受。
- **不做什么：** 不改 `Compare with Current/Parent`、`Checkout Revision`、`Rewrite Author Identity…` 等已可接受的术语；不改 GitOperationService 的 confirmLabel 文案（对话框内标签与菜单解耦）。

## 实施位置

`webview/src/ContextMenu.tsx#commitKindMenu`（决策 1/3/5）、`webview/src/ContextMenu.tsx#headKindMenu`（决策 2）、`webview/src/ContextMenu.tsx#refKindMenu`（决策 4）。

## 下一步

无需后续动作。
